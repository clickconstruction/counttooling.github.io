# T1-04 — Sheet correction flows into an escapable two-point verify

Plan of record for CountTooling Tier-1 item #4 (JOURNEY-MAP.md "Ranked improvement
shortlist", Tier 1 row 4). Execute from the repo root. Read AGENTS.md first for house
conventions (registry rules, docs tables, test naming, sw/precache discipline). All line
numbers below were verified against the working tree on 2026-08-09 — re-verify with the
quoted grep anchors before editing; app.js especially drifts.

## Problem (verified)

On a non-standard sheet size, the Set Scale modal's sheet-correction dropdown pre-selects
its best-guess sheet (`refreshSheetWarning`, features/scale.js:54-75 — `sel.value =
a.bestGuessSheet ? a.bestGuessSheet.id : ''` at :72), and one honest click on a preset (or
a custom fraction Apply) silently folds that correction into the page scale via
`withSheetCorrection` (features/scale.js:78-86, called at :263 for presets and :331 for
custom). Reproduced on the sample plan (J3 dossier, journeys/set-a-scale-you-can-trust.md
findings #1/#6, re-driven live 2026-08-09): warning up, ANSI D pre-selected, the 1/8"
preset lands `{pixelsPerUnit: 3.375, correctionFactor: 0.375, label: '1/8" = 1' · ANSI
D'}` where the sheet's true scale is 9 px/ft — every length reads 2.67× long, a printed
65'-0" wall measures 173'-1", and J5's labeled 25-ft corridor read 66.59 ft
(journeys/measure-runs.md finding #4). The only guards are a 2-second toast ("Scale set —
verify it against a known dimension", :269/:337), the tiny "· ANSI D" chip suffix, and a
Verify button the user must discover on their own; "Non-standard — don't correct" is the
last of 17 dropdown options (:70-71) and the choice is not remembered on reopen
(`refreshSheetWarning` re-guesses every presets-tab show). The trap sits directly on the
daily-core drawing happy path (J3 J5 J6 J7); a wrong scale ruins the whole bid.

The existing verify machinery already catches this perfectly when invoked: `startScaleCheck`
(features/scale.js:177-189) arms a two-point pick with `state.scaleCheckMode = true`, the
canvas commit (app.js:4552-4563) reopens the modal, `openScaleModal` routes to the check
panel (features/scale.js:111-128), and Check/Use-measured (:364-399) shows the % error and
recalibrates — the J3 walk showed it catching the bad correction in one pass ("Off by
about 166.6% … Use measured to fix it"). The fix is to hand corrected applies straight
into that machinery instead of a toast.

**Verifier caveat (binding):** the hand-off must be escapable — Esc/skip keeps the applied
scale — otherwise it adds mandatory clicks on genuinely compressed prints where the guess
is right, and fails the proposal's own spirit test (J3 Proposals, "rework" row).

## Design

All app changes live in **features/scale.js** (plus one telemetry migration). No new UI
surface, no new modal, no new CSS: the change re-routes two existing apply paths into the
existing verify flow.

### features/scale.js

1. **Preset apply** (the `btn.onclick` built in `showScaleTab('presets')`,
   features/scale.js:258-270). Before building the scale object, capture the live
   correction: `const corrected = activeSheetCorrection` (non-null only when a correction
   is in play — cleared for zone mode, standard sheets, and the explicit "don't correct"
   choice, so all three keep today's behavior automatically). After the existing
   `page.scale = withSheetCorrection(...)` + `App.markProjectDirty()` +
   `App.shareViewerScale(...)`:
   - **corrected falsy (unchanged path):** keep the current tail exactly — `hideModal`,
     `updateUI`, `renderAnnotations`, toast "Scale set — verify it against a known
     dimension".
   - **corrected truthy (new path):** call `startScaleCheck()` (it hides the modal, sets
     `state.scaleCheckMode = true`, arms `TOOL.SCALE`/`POINT_A`, and runs
     `updateUI`/`renderAnnotations` itself — do not duplicate those), then toast:
     `'Scale set as if printed on <sheet label> — click both ends of a printed dimension to check it (Esc keeps this scale)'`.
     Resolve the sheet label from `App.STANDARD_SHEETS` by `corrected.sheetId` (same
     lookup `withSheetCorrection` does at :80). This copy subsumes J6's at-apply warning
     polish ("as if printed on…" phrasing, multi-scale-and-repeats.md Proposals) — do not
     also build that separate toast/button.
2. **Custom apply** (`#scaleCustomApply` handler, features/scale.js:314-338): identical
   branch after its `withSheetCorrection` apply at :331. This subsumes J3's custom-entry
   papercut (finding #6 — the correction explainer sits far from the Custom section; now
   the hand-off itself announces it).
3. **Escapability — verify, don't build.** Nothing to add; confirm these paths in the spec:
   - Esc mid-pick (modal closed, `TOOL.SCALE` armed): app.js:5853-5863 clears the tool +
     `App.resetScaleCheckMode` — the applied `page.scale` is untouched.
   - Esc with the check panel open: app.js:5789-5794 (scaleModal Esc branch) same reset.
   - Check-panel "Cancel" / "Keep current scale" (`#scaleCheckCancel`,
     features/scale.js:400-407) keeps the applied scale.
   - The check flow never overwrites until "Use measured" (comment at :111-113;
     `applyTwoPointScale` only runs from `#scaleSet` and `#scaleCheckUseMeasured`).
4. **Telemetry** (see section below): `App.logUserEvent` calls at the apply sites and the
   Check handler. `App.logUserEvent` is published at app.js:6158; the feature-file pattern
   is `App.logUserEvent('export_pdf', …)` in features/output.js:401.

### supabase/migrations/

`log_user_event` has a **server-side event-type allowlist**
(supabase/migrations/20260326230000_user_presence_and_activity.sql:43-61 — `p_event_type
not in ('session_start', 'project_open', …)` raises). Add a new migration
`supabase/migrations/<timestamp>_scale_set_events.sql` that re-creates the function with
`'scale_set', 'scale_verify'` appended to the allowlist (copy the LATEST deployed function
body — if another Phase-4 branch already re-created `log_user_event` with its own event
types, e.g. T1-01's restore events, build on that body, not the original 20260326230000
one; keep security definer + search_path). Per AGENTS.md, apply it via the Supabase MCP
`apply_migration` tool (name = filename without `.sql`). The admin activity feed renders
`event_type` and metadata verbatim (format.js:135-148), so no client formatting work.

### What does NOT change

- **Standard-sheet preset/custom applies** — `activeSheetCorrection` is null, so the toast
  path runs exactly as today.
- **"Non-standard — don't correct"** chosen in the dropdown — correction is null, no
  hand-off (the user explicitly opted out).
- **Two-point applies** (`applyTwoPointScale`) — already ground truth, never corrected, no
  hand-off.
- **Zone-target applies** — the `if (applyScaleObjectToZoneOrPage(scaleObj)) return;`
  early-outs at :260/:328 stay first in both handlers; zones remain uncorrected here
  (that's Tier-1 item #7's separate change — see Risks).
- The correction mechanism itself: `refreshSheetWarning`, the warning box, the dropdown,
  `withSheetCorrection`, `sheetCorrectionFactor` — untouched.
- The check panel's markup (app/index.html:510-543) and mechanics — untouched.

### Simplicity budget

Removes: the need to ever discover the Verify button on corrected pages; the silent-2.67×
outcome; the apply → find sidebar badge → reopen → Verify 4-surface trek (collapsed into
one continuous gesture); the plain post-apply toast on the corrected path (replaced, not
added-to). Adds: one branch + one coaching string per apply site, zero new DOM, zero new
state (reuses `scaleCheckMode`), zero new CSS.

## Tests

Extend **scale.spec.js** (Playwright; it owns this surface — `*.spec.js` = Playwright,
`*.test.js` = Node, enforced by playwright.config.js testMatch). To get a correction in
play on the standard-size test PDF, stub the analysis in-page before opening the modal —
the same technique scripts/build-screenshots.js uses:

```js
await page.evaluate(() => {
  window.App.getPageSheetAnalysis = () => ({
    widthPt: 1224, heightPt: 792, isStandard: false,
    bestGuessSheet: window.App.STANDARD_SHEETS.find(s => s.id === 'ANSI_D')
  });
});
```

(`App.getPageSheetAnalysis` / `App.STANDARD_SHEETS` / `App.sheetCorrectionFactor` are
published at app.js:6302-6304; the real `sheetCorrectionFactor` then computes a real
factor.) New tests, in the existing `test.describe('window.App registry pilot - Scale
modal')`:

1. `'correction-in-play preset apply flows into the two-point verify; Esc keeps the applied scale'`
   — stub analysis, open modal, assert `#scaleSheetWarning` visible and select pre-set;
   click a preset; assert modal hidden, `state.scaleCheckMode === true`,
   `state.tool === App.TOOL.SCALE`, and `page.scale.correctionFactor` set; press Escape;
   assert tool back to NONE, `scaleCheckMode === false`, and `page.scale` (incl.
   correctionFactor) unchanged.
2. `'correction-in-play custom apply hands off; standard sheet keeps the plain toast'` —
   custom fraction + feet → same hand-off assertions; then un-stub (reload or restore),
   apply a preset on the standard sheet and assert NO hand-off (`scaleCheckMode` false,
   tool NONE, modal hidden — today's behavior).
3. `'verify hand-off completes: Check shows the delta, Use measured recalibrates'` — after
   the hand-off, click two canvas points ≥1px apart; assert scaleModal reopens with
   `#scaleCheckPanel` visible; fill `#scaleCheckValue`, click `#scaleCheckBtn`, assert
   `#scaleCheckResult` visible; click `#scaleCheckUseMeasured`; assert
   `page.scale.pixelsPerUnit` recalibrated, `correctionFactor` absent, `refLine` stamped,
   modal closed. Also assert the "Keep current scale" branch (`#scaleCheckCancel` after
   Check) leaves the corrected scale in place.

No new Node unit test: the change adds no pure logic (`sheetCorrectionFactor` and
`scaleCheckDelta` are already pinned in geometry.test.js). Run `npx playwright test
scale.spec.js` locally; the full suite via `npm test`.

## Telemetry

Per the shortlist row (`scale_set` carries correctionFactor + verify outcome) and the
standing rule (J3 is telemetry-blind — features/scale.js contains zero `logUserEvent`
calls today; the J3 dossier names this "the cheapest blind spot"):

- `scale_set` — fired at every **page-scale** apply in features/scale.js
  (preset onclick, `#scaleCustomApply`, and `applyTwoPointScale`'s page branch), metadata:
  `{ method: 'preset'|'custom'|'two-point'|'use-measured', correctionFactor: <number|null>,
  pixelsPerUnit, unit, verifyHandoff: <bool>, pageIndex: state.currentPage }`. Give
  `applyTwoPointScale` an optional `method` argument defaulting `'two-point'`;
  `#scaleCheckUseMeasured` passes `'use-measured'`. Zone-target applies are NOT logged here
  (item #7 folds in the zone flavor later).
- `scale_verify` — fired in the `#scaleCheckBtn` handler after `scaleCheckDelta`
  (features/scale.js:375), metadata: `{ deltaPct, correctionFactor: <the page scale's, or
  null>, pageIndex }`. Verify outcome is then readable from the event stream: a
  `scale_set{verifyHandoff:true}` followed by `scale_verify` + `scale_set{method:
  'use-measured'}` = corrected-and-fixed; followed by nothing = escaped/kept. (Explicitly
  out of scope: logging the Esc paths themselves — they live in app.js's Escape ladder and
  aren't worth the wiring.)
- `logUserEvent` already no-ops when Supabase is disabled or signed out (app.js:2743) —
  keep the app fully functional with Supabase disabled (house rule).
- Requires the allowlist migration described in Design.

## Risks & edge cases

- **T1-03 collision (fix in flight):** the Set Scale modal height clamp is being fixed in
  a separate session, and its shortlist row says "add `scale_set` while in the file". If
  that branch lands first with a `scale_set` call and/or the allowlist migration, EXTEND
  its metadata to this plan's shape rather than re-adding, and skip the duplicate
  migration. Rebase features/scale.js carefully.
- **T1-07 seam (zone correction carry):** item #7 will edit the same two apply handlers
  around the `applyScaleObjectToZoneOrPage` early-outs (features/scale.js:260/:328) and
  fold a zone flavor into `scale_set`. Keep this change's branches strictly after those
  early-outs so either item can land first.
- **Toast swallows the first verify click:** toasts are full-screen click-swallowing
  overlays (Tier-2 #15; J6 finding #4 — `#airboardToastModal` is `inset:0,
  pointer-events:auto`). The coaching toast will eat canvas clicks for its ~2s default —
  same exposure as today's "Scale set —" toast, but now the user is being asked to click.
  Accept for now (keep the default duration, don't extend it); T2 #15's non-blocking
  corner toasts dissolve this entirely. Do not fix toast behavior in this branch.
- **Lingering `scaleCheckMode` if the user arms another tool mid-verify** (hotkey D/L/etc.
  instead of Esc): pre-existing with the Verify button — `scaleCheckMode` survives until an
  exit path calls `resetScaleCheckMode`, so a later manual two-point set could route into
  the check panel unexpectedly. `setScaleClick` (features/scale.js:276-285) already resets
  it for the S/openers path. More exposure now; accept and note, don't chase it into the
  HOTKEYS table — if it bites in bake-in, the fix is a `resetScaleCheckMode` call in the
  tool-arming helpers.
- **Viewers:** `TOOL.SCALE` is viewer-allowed (app.js:2097/:4528) and viewer presets hit
  the same correction trap (J3 verification, stubbed view link) — the hand-off works for
  viewers unmodified; "Use measured" shares back via `App.shareViewerScale`
  (features/scale.js:203, guarded). No extra work; just don't gate the hand-off on
  `!state.isViewer`.
- **Near-1.0 corrections:** a barely-off sheet still triggers the hand-off (any
  non-standard analysis with a guess). Acceptable — the analysis already declares the page
  non-standard; don't add a threshold.
- **Undo depth:** preset apply and Use-measured each push a snapshot (:261, :199) — two
  Ctrl+Z to fully revert a corrected-then-recalibrated page. Unchanged from today's manual
  verify; no action.
- **Double-tap guard:** the two-point commit path has a 400ms double-tap guard
  (app.js:4555) — the hand-off arms the tool before any click, so no interaction.

## Acceptance criteria

1. On a page where the sheet warning shows with a pre-selected correction, clicking any
   preset applies the corrected scale (`page.scale.correctionFactor` set, label carries
   the sheet suffix) AND immediately arms the two-point verify (modal hidden,
   `state.scaleCheckMode === true`, `state.tool === TOOL.SCALE`), with a toast naming the
   assumed sheet and the Esc escape.
2. Custom fraction Apply behaves identically when a correction is in play.
3. Esc at any stage — before point A, between A and B, or in the check panel — returns to
   Move with the applied (corrected) scale fully intact; so does "Keep current scale".
4. Completing the verify: two plan clicks reopen the modal on the check panel; Check shows
   Expected / Current-scale-reads / delta; "Use measured" recalibrates the page scale
   (refLine stamped, correctionFactor gone).
5. Standard-sheet and "Non-standard — don't correct" applies behave byte-for-byte as
   today (toast, no hand-off); zone-target applies are untouched.
6. Signed in with Supabase enabled, `scale_set` fires on every page-scale apply with
   `{method, correctionFactor, pixelsPerUnit, unit, verifyHandoff, pageIndex}` and
   `scale_verify` fires on Check with `deltaPct`; with Supabase disabled or signed out the
   flows work identically with no errors.
7. `npm run check` passes (including build:sw and build:guides staleness checks);
   `npx playwright test scale.spec.js` passes including the three new cases; ARCHITECTURE
   /FEATURES/FEATURE-CATALOG rows and the two guides reflect the new behavior.
