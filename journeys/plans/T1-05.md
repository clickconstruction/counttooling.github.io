## Problem (verified)

A line drawn on a page with no scale is measured in raw PDF points
(`line-metrics.js:88-92` — `lineLengthFeetForTotals` "returns the raw value
(PDF-pts) when there is no scale"), and every rollup surface sums those points
straight into a feet total: the label is chosen by `pickScaleForLineType`
(report.js:17-30 and the surfaces' `App.pickScaleForLineType` calls), which says
"ft" whenever *any* page in the set has a scale. Reproduced end-to-end: page 1
scaled (34.00 ft of line) + page 2 unscaled (367.2 raw pts) → Copy Summary
copied `• 401.20 ft of PVC waste 3"` with zero warning; true total after scaling
is 74.80 ft — a 5×-wrong number an estimator prices a bid from. The same wrong
"401.20 ft" shows simultaneously in the footer totals, the sidebar Summary, the
sidebar Line Types badge, the Lines-list type rollup, the on-canvas legend
(scale-zone mixed case), and the Takeoff Report headline. Two adjacent leaks make
it reachable by normal use: (a) the "Set Scale first" gate runs only when *arming*
a line tool (`app.js:3036-3040` quickLine, `:3050-3053` polyline, `:3010` measure)
— an armed tool page-flipped onto an unscaled sheet keeps placing lines (real-click
verified: no toast, footer went 225.00 → 408.40 ft); and (b) only Copy to /Tooling
runs the pre-export scale check (`features/output.js:132-149 runToolingExport`) —
Copy Summary (`output.js:265-277` → `doCopyEmailSummary:248`) bypasses it entirely.
A verified sharpening: even "Export anyway" on a mixed-scale line type emits a
ft-labeled mixed sum (`ft of X⇥401.20⇥1, 2`), because the `px of` label at
report.js:314-318 only fires when *no* page of the type has a scale. The honest
model already ships in this codebase: the Summary drill-down and the report's
per-page rows say "200 px", and the Rooms section excludes unscaled boxes with a
footnote (report.js:408 email suffix "— some boxes missing scale"; buildReportHtml
"* Some boxes are on pages without a scale…").

## Design

One principle, three parts: **(1)** lengths accumulate in two buckets — feet
(lines with an effective scale) and px (lines without) — and no surface ever adds
the buckets together; **(2)** the existing pre-export scale check also gates Copy
Summary; **(3)** the arm-time scale gate re-fires on page switch while a line tool
is armed.

### Part 1 — the ft/px split (root fix)

**`line-metrics.js`** — add one pure primitive next to `lineLengthFeetForTotals`
(line 88), same argument shape, exported in the guarded CommonJS footer:

```js
// Split total: { feet, px }. feet = multiply-zone-adjusted length converted to
// feet for lines with a usable effective scale (same test the export gate uses:
// eff && eff.pixelsPerUnit); px = raw PDF-pts for the rest. Exactly one bucket
// is non-zero per line — rollups must NEVER add the buckets together.
function lineLengthSplitForTotals(line, isPoly, ann, pageScale, lineType) {
  const eff = effectiveScaleForLine(ann, line, isPoly, pageScale);
  const len = lineLengthForTotals(line, isPoly, ann, pageScale, lineType);
  if (eff && eff.pixelsPerUnit) return { feet: convertUnitValue(len, eff.unit || 'ft', 'ft'), px: 0 };
  return { feet: 0, px: len };
}
```

Note the scaled-ness test is `eff && eff.pixelsPerUnit` — the same test
`collectUnscaledLinePages` uses (output.js:125), so the gate and the totals can
never disagree. (`lineLengthFeetForTotals` tests `eff && eff.unit`; do not copy
that.) `lineLengthFeetForTotals` itself stays untouched — per-line surfaces
(`getLineRealWorldLengthFeet`, item details, drill-down) keep using it.

**`app.js`** — thin state-resolving wrapper next to `getLineLengthFeetForTotals`
(app.js:790), mirroring its shape exactly:
`function getLineLengthSplitForTotals(line, pageIdx, isPoly, ann)`. Publish it
three ways: `window.getLineLengthSplitForTotals = …` beside line 804 (report.js
consumes it), `App.getLineLengthSplitForTotals = …` in the registry tail beside
line 6310 (features consume it), and add it to the `createCanvasDraw` deps object
(app.js:1539 block, beside the existing `getLineLengthFeetForTotals` entry) for
drawLegend.

**`geometry.js`** — one shared formatter beside `formatFeet` (geometry.js:175),
exported in the module footer, byte-identical to today's output in the pure cases
so render-pixel baselines and existing spec assertions don't move:

```js
// "12.50 ft" | "200 px" | "12.50 ft + 200 px" | "0" — never sums px under ft.
function formatFeetPx(feet, px) {
  const ftStr = feet > 0 ? feet.toFixed(2) + ' ft' : '';
  const pxStr = px > 0 ? Math.round(px) + ' px' : '';
  if (ftStr && pxStr) return ftStr + ' + ' + pxStr;
  return ftStr || pxStr || '0';
}
```

Publish `App.formatFeetPx` beside `App.formatFeet` (app.js:6311). (Cosmetic
delta: an empty takeoff footer that today reads `0.00 ft` when a page happens to
be scaled will read `0` — acceptable; J18 Friction #8 already flags that state.)

### Part 3 — re-check the gate on page switch

`app.js` — currently the `showSetScaleFirstToast` gate lives only in the tool-arm
onclicks (:3010 Measure, :3037 Quick Line, :3052 Polyline, :3082/:4639/:5514
Scale Zone, :3104/:4670/:5498 Room Sizer). Page navigation has ~10 entry points
(`#prevPage`/`#nextPage` :3461-3462, marked-page jumps, arrow hotkeys,
pages-list.js:52, lines-list.js:133, item-details.js:153, room-sizer.js:414,
output.js:170 GoSet), so hook the one sink they all reach: **`renderPdf`**
(app.js:1233). Near the top:

```js
// T1-05: the Set-Scale gate only ran at tool-arm; an armed line tool page-
// flipped onto an unscaled sheet kept placing px-measured lines. Re-check on
// every page change (renderPdf is the sink for all ~10 nav entry points).
let scaleGatePage = -1;
function recheckScaleGateOnPageSwitch() {
  if (state.currentPage === scaleGatePage) return;
  scaleGatePage = state.currentPage;
  const gated = { [TOOL.LINE]: 'Quick Line', [TOOL.POLYLINE]: 'Polyline',
    [TOOL.MEASURE]: 'Measure', [TOOL.SCALE_ZONE]: 'Scale Zone', [TOOL.ROOM]: 'Room Sizer' };
  const toolName = gated[state.tool];
  if (!toolName || !state.pages.length || getPageScale(state.currentPage)) return;
  // Same reset as the Move button (app.js:3021-3034): drop to Move + clear starts.
  state.tool = TOOL.NONE;
  state.quickLineStart = null; state.scaleZoneStart = null; state.roomBoxStart = null;
  if (state.scalePointA || state.scalePointB) { state.scalePointA = null; state.scalePointB = null; state.scaleMode = SCALE_MODES.NONE; }
  showSetScaleFirstToast(toolName);
  logUserEvent('unscaled_ft_block', state.currentProjectId || null, { surface: 'page-switch' });
  updateUI();
}
```

Call it inside `renderPdf` right after `const page = state.pages[state.currentPage];`
(:1250). The `scaleGatePage` guard makes it O(1) on the zoom/pan renders that also
route through renderPdf. The gated-tool set matches exactly the tools whose arm
path calls `showSetScaleFirstToast` — Counter/Note/Highlight/Multiply/Delete
zones need no scale and must not disarm. Reuses the existing toast verbatim
(same words, same 3s timer — no new copy). Boot/restore paths set
`currentPage` with no tool armed, so the check no-ops there; a fresh PDF load
resets tools anyway. Same known looseness as the arm gate: it checks
`getPageScale` only (a page covered by scale zones but no page scale still
disarms) — deliberate, to match arm behavior 1:1.

## Acceptance criteria

   Summary row, Line Types badge, Lines-list rollup, and legend all read
   `10.00 ft + 367 px` (or their surface's equivalent) — the string `377` appears
   on no surface, in no export.
2. `getPipeToolingSummary()` emits two rows for that type — `ft of X⇥10.00⇥1`
   and `px of X⇥367⇥2`; `getEmailTextSummary()` emits two bullets; the report
   headline reads `10.00 ft total length (+ 367 px on unscaled pages)` and its
   Summary table shows split rows with the px footnote.
3. All-scaled projects produce byte-identical output to today on every surface
   (copy-tooling-feet.spec.js's existing 10.00-ft-everywhere test still passes
   untouched).
4. Clicking any Copy Summary scope option with an unscaled line page opens
   `#toolingScaleCheckModal` (listing the flagged page labels) and writes nothing
   to the clipboard; Cancel/Escape drops the pending copy; "Export anyway" copies
   text whose unscaled lengths appear only in `px of` rows; Copy to /Tooling
   behaves exactly as before.
5. With Quick Line (or Polyline/Measure/Scale Zone/Room Sizer) armed, navigating
   to an unscaled page by any route (footer arrows, arrow keys, pages list,
   Lines-list jump) shows the existing "Set Scale ⚖ first…" toast, drops the
