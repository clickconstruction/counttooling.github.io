Plan of record for CountTooling Tier-1 item #7 (JOURNEY-MAP.md "Ranked improvement
shortlist", Tier 1 row 7). **Approved by Will 2026-08-09: carry the correction into
zones** — the in-code skip is overridden by product decision. Execute from the repo root.
Read AGENTS.md first for house conventions (registry rules, docs tables, test naming,
sw/precache discipline). All line numbers below were verified against the working tree on
2026-08-10 — re-verify with the quoted grep anchors before editing (`grep -n "zone

## Problem (verified)

The Set Scale modal doubles as the scale-zone create/edit dialog
(`state.scaleModalApplyTarget === 'zone'`), and in zone mode it deliberately skips the
sheet-size correction the page scale carries: `refreshSheetWarning` early-returns for
zone targets (features/scale.js:59 — `if (state.scaleModalApplyTarget === 'zone') {
clearSheetCorrection(); return; }`), and both zone apply paths carry an explicit `// zone
target: no sheet correction` comment (features/scale.js:260 preset, :328 custom), per the
header design note "PAGE SCALE ONLY — never zones (which inherit the page scale)"
(features/scale.js:33-37). But zone *presets don't inherit anything* — they store the raw
preset `pixelsPerUnit`. Reproduced end-to-end by the J6 verifier
(journeys/multi-scale-and-repeats.md finding #10, CONFIRMED, img/multi-scale-and-repeats-08.png):
with the dialog's own preselected ANSI-D correction accepted for the page (chip
`1/8" = 1' · ANSI D`, stored `pixelsPerUnit: 3.375, correctionFactor: 0.375`), a 1/4"
zone preset stored raw `pixelsPerUnit: 18` — zone/page ratio 5.33 where a consistent
1/4-vs-1/8 pair is exactly 2, and the same horizontal span measured **9'-2" inside** the
zone vs **49'-0" outside**, a silent 2.67× disagreement with no warning anywhere. On
exactly the compressed sheets the app detects and corrects for, every scale-zone preset
number is silently wrong relative to the page, and detail counts land in the bid at the
wrong lengths.

The approved fix (J6 Proposals, "rework" row, spiritPass verified): when the page scale
holds a `correctionFactor`, apply the same factor to zone preset/custom entries and show
the same "as if printed on ANSI D" note in the zone dialog. **Two-point zone calibration
stays untouched** — it is already ground truth (it measures real on-screen pixels, no
`72 pt = 1 in` assumption).

## Design

All app changes live in **features/scale.js**. No new UI surface, no new modal, no new
CSS, no new persisted setting: one small helper, two wrapped call arguments, one
info-line sentence, one telemetry call. (Plus, conditionally, one Supabase migration —
see Telemetry.)

### features/scale.js

1. **New helper `withZoneSheetCorrection(scaleObj)`**, placed next to
   `withSheetCorrection` (:78-86) and mirroring its mutate-and-return shape. Zone mode
   cannot use `activeSheetCorrection` (correctly cleared by `refreshSheetWarning`'s :59
   early-return — leave that in place; the warning/picker UI must NOT appear in zone
   mode, because the sheet decision was already made at page-scale time). Instead read
   the correction the page scale itself carries:

   ```js
   // Zones inherit the page's sheet correction (product decision 2026-08-09):
   // a zone preset/custom entry assumes true print size exactly like a page
   // preset does, and the page already knows this sheet was compressed. Reads
   // the stamped factor off page.scale (activeSheetCorrection is cleared in
   // zone mode). Two-point zone calibration never comes through here — it is
   // already ground truth.
   function withZoneSheetCorrection(scaleObj) {
     const state = App.state;
     if (state.scaleModalApplyTarget !== 'zone') return scaleObj;
     const ps = state.pages[state.currentPage]?.scale;
     if (!ps || !ps.correctionFactor) return scaleObj;
     scaleObj.pixelsPerUnit *= ps.correctionFactor;
     scaleObj.correctionFactor = ps.correctionFactor;
     if (ps.sheetSize) {
       scaleObj.sheetSize = ps.sheetSize;
       if (scaleObj.label) scaleObj.label += ' · ' + ps.sheetSize.replace('_', ' ');
     }
     return scaleObj;
   }
   ```

   The label suffix matches `withSheetCorrection`'s (`sheet.id.replace('_', ' ')`, :84),
   so the on-canvas zone label (canvas-draw.js:432-451 renders `zone.scale.label`) and
   the edit-mode "Current: …" info line (features/scale.js:146-147) show the ` · ANSI D`
   trace for free.

2. **Preset apply** (the `btn.onclick` built in `showScaleTab('presets')`, :258-260):
   wrap the early-out's argument and retire the stale comment —

   ```js
   if (applyScaleObjectToZoneOrPage(withZoneSheetCorrection(scaleObj))) return;   // zone: inherits the page's sheet correction
   ```

   The helper no-ops for page targets, so the page path is byte-identical.

3. **Custom apply** (`#scaleCustomApply` handler, :314-338): identical wrap at :328.

4. **Two-point untouched — this is why the correction lives at the two call sites and
   not inside `applyScaleObjectToZoneOrPage`.** `applyTwoPointScale` (:193-212) calls
   `applyScaleObjectToZoneOrPage(scaleObj)` directly at :198 and must keep bypassing the
   helper. Do not move the correction into `applyScaleObjectToZoneOrPage`.

5. **Dialog note** — in `openScaleModal`'s zone branch (:141-153), after `scaleInfo` is
   set (both the edit variant :147 and the create variant :149), append the page's
   correction disclosure when one is in play:

   ```js
   const ps = state.pages[state.currentPage]?.scale;
   if (ps?.correctionFactor) {
     const sheetName = ps.sheetSize ? ps.sheetSize.replace('_', ' ') : 'the corrected sheet';
     scaleInfo.textContent += ' Presets here are corrected as if printed on ' + sheetName + ', matching the page scale.';
   }
   ```

   This reuses the "as if printed on …" trade phrasing from T1-04's page-apply toast.
   **No new toast in zone mode** — the dialog note is the disclosure. Deliberate: a toast
   at the measure→zone hand-off would feed the click-swallowing overlay problem (J6
   friction #4 / Tier-2 #15); do not add one.

6. **Header comment rewrite** (:33-37): the "PAGE SCALE ONLY — never zones (which
   inherit the page scale)" sentence is now false in both halves. Rewrite to: the warning
   banner/picker is primed on the page-scale presets tab only; zone preset/custom applies
   inherit the page's *stamped* factor via `withZoneSheetCorrection` (product decision
   2026-08-09); two-point calibration is never corrected (ground truth).

7. **Telemetry** (see section below): one `App.logUserEvent('scale_set', …)` zone-flavor
   call inside `applyScaleObjectToZoneOrPage`, with a `method` parameter threaded from
   its three callers.

### What does NOT change

- **Two-point zone calibration** (`#scaleSelectOnPdf` in zone mode → canvas clicks →
  `#scaleSet` → `applyTwoPointScale` → `applyScaleObjectToZoneOrPage`) — raw measured
  pixels, never corrected.
- **Page-scale applies** — `withZoneSheetCorrection` no-ops when the target isn't
  `'zone'`; `withSheetCorrection`, `refreshSheetWarning`, the warning banner, the
  dropdown, and (if T1-04 has landed) the verify hand-off are untouched.
- **`refreshSheetWarning`'s zone early-return (:59)** stays — no `#scaleSheetWarning`
  banner or `#scaleSheetSelect` picker in zone mode, ever. The zone inherits; it doesn't
  re-ask.
- **Zone create/edit entry flows in app.js** (gate toast, two-corner click, context-menu
  Edit at app.js:4332-4333, `pendingScaleZone` priming at app.js:4657) — untouched.
- **Rendering and math consumers** — canvas-draw.js's zone label uses `sc.label`
  (:432-433) and line-metrics.js's `getEffectiveScaleForLine` uses only
  `eff.pixelsPerUnit` (line-metrics.js:70-76), so the stamped
  `correctionFactor`/`sheetSize` fields are inert metadata exactly as they are on
  `page.scale`. No double-correction is possible: the factor is folded into
  `pixelsPerUnit` once, at apply time.
- **Save/load/export/import** — `zone.scale` is stored and serialized as a whole object
  (`scale: { ...scaleObj }`, features/scale.js:230/:232; scaleZones ride
  `canvas.annotations` wholesale), so the new fields persist with zero schema work. No
  `makeAnnotations` change — no new annotation kind, just fields on an existing nested
  object.
- **Existing zones** scaled before this fix keep their raw values — values stamp at
  apply time, same semantics as `page.scale`. Re-applying the zone's preset via
  right-click → Edit scale refreshes it. No retroactive migration.

### Simplicity budget

Removes: a silent 2.67× error class on every corrected sheet; the need to even know the
sheet was compressed when scaling a detail; both stale `// zone target: no sheet
correction` comments and the now-false header claim. The preset just reads right — an
invisible fix. Adds: one ~15-line helper, two wrapped arguments, one appended sentence in
an existing info line, one telemetry call. Zero new DOM, zero new CSS, zero new state.

## Telemetry

Per the shortlist row: **fold into `scale_set` (zone flavor)** — J6 is telemetry-blind
and features/scale.js contains zero `logUserEvent` calls today (standing rule: every
rework ships its own event).

- Give `applyScaleObjectToZoneOrPage(scaleObj, method)` an optional second parameter;
  after the commit (post the scaleZones write, before returning true) fire:

  ```js
  App.logUserEvent && App.logUserEvent('scale_set', App.state.currentProjectId, {
    target: 'zone',
    method: method || 'two-point',            // 'preset' | 'custom' | 'two-point'
    pixelsPerUnit: scaleObj.pixelsPerUnit,
    unit: scaleObj.unit,
    correctionFactor: scaleObj.correctionFactor || null,
    pageIndex: App.state.currentPage,
    edit: !!edit
  });
  ```

  Callers pass the method: preset onclick `'preset'`, `#scaleCustomApply` `'custom'`,
  `applyTwoPointScale` `'two-point'` (default). T1-04's page-flavor `scale_set` events
  carry no `target` key — zone events are distinguishable by `target: 'zone'`; do not
  touch T1-04's calls or shape.
- `logUserEvent` (app.js:2742, published as `App.logUserEvent` at app.js:6158) already
  no-ops when Supabase is disabled or signed out — the house "works with Supabase
  disabled" rule holds with no extra guard. Feature-file precedent:
  `App.logUserEvent('export_pdf', …)` at features/output.js:401.
- **Migration (conditional):** `log_user_event` has a server-side event-type allowlist
  (supabase/migrations/20260326230000_user_presence_and_activity.sql:53-57 — unknown
  types raise). T1-04's plan owns the `scale_set`/`scale_verify` allowlist migration.
  Before writing one, check `grep -rn "scale_set" supabase/migrations/`: if T1-04 (or
  T1-03's opportunistic add) already landed it, skip. If this branch lands first, create

## Risks & edge cases

- **T1-04 merge order (binding, same file, same two handler lines).** T1-04 ("correction
  flows into two-point verify") edits the SAME preset onclick and `#scaleCustomApply`
  handlers, adding page-path branches strictly *after* the
  `applyScaleObjectToZoneOrPage` early-outs at :260/:328; this item wraps the early-outs'
  *argument*. The edits are semantically independent (zone path vs page path) but
  textually adjacent, so a rebase conflict in those two hunks is expected. **Preferred
  order: T1-04 lands first, this branch rebases on top** (the wrap is mechanical). If
  this lands first, T1-04 rebases instead. Either way: the first branch to land ships the
  `scale_set` allowlist migration and the second skips it; keep both telemetry shapes as
  written (page events no `target`, zone events `target: 'zone'`).
- **T1-03 collision (fix in flight, separate session):** the modal-height clamp touches
  styles.css but its shortlist row says "add `scale_set` while in the file". Before
  merging, grep the tree for an existing `scale_set` call/migration and extend rather
  than duplicate.
- **Pre-existing zones keep raw values.** Zones scaled before this fix (or while the
  page was uncorrected) are not retroactively rewritten — same stamp-at-apply-time
  semantics as `page.scale`. The visible trace is the *absence* of the sheet suffix on
  the zone label. Accept; right-click → Edit scale → preset refreshes any zone.
- **Page scale recalibrated after zones exist.** If the user later two-points the page
  (correction gone, ground truth), previously corrected zones keep their stamped factor.
  Consistent with page semantics and traceable via the label suffix; do not build a
  re-sync. Conversely a zone created after that recalibration correctly gets no
  correction (`page.scale.correctionFactor` is absent).
- **Page scale missing on the edit path.** Zone creation is gated on a page scale ("Set
  Scale ⚖ first to use Scale Zone."), but the edit path is defensive anyway — the
  helper's `state.pages[state.currentPage]?.scale` optional chain no-ops safely.
- **No zone-mode toast, on purpose** — the disclosure lives in the dialog info line.
  Adding a toast would re-feed the click-swallowing overlay trap at the measure→zone
  hand-off (J6 friction #4; Tier-2 #15 owns toast behavior). Do not fix or add toasts in
  this branch.
- **Viewers:** both zone tools are in `viewerHideIds` (app.js:2119) — viewers cannot
  create or edit zones, so no viewer surface changes and `shareViewerScale` (page-only)
  is never involved in the zone path.
- **Label width:** the ` · ANSI D` suffix widens the on-canvas zone label;
  canvas-draw.js only draws it for zones ≥ 30×20 px and paints a background box —
  cosmetic, no action.
- **Undo:** `applyScaleObjectToZoneOrPage` already pushes a snapshot (:216); one Ctrl+Z
  reverts a corrected zone apply, unchanged from today.

## Acceptance criteria

1. On a page whose scale carries a `correctionFactor` (e.g. `1/8" = 1' · ANSI D`,
   3.375 px/ft), opening the zone scale dialog (create or edit) shows the info line
   ending "…corrected as if printed on ANSI D, matching the page scale.", and the
   `#scaleSheetWarning` banner/picker does NOT appear.
2. Clicking the 1/4" preset for that zone stores `pixelsPerUnit = 18 ×
   page.correctionFactor`, stamps `correctionFactor` + `sheetSize`, and the zone's
   on-canvas label reads `1/4" = 1' · ANSI D`. Measuring the same span inside and
   outside the zone now disagrees by exactly the presets' nominal ratio (2× for 1/4 vs
   1/8), not 2.67× that.
3. A custom fraction Apply in zone mode behaves identically.
4. Two-point zone calibration (Select on PDF inside zone mode → `#scaleSet`) stores the
   raw measured `pixelsPerUnit` with no `correctionFactor` — byte-for-byte today's
   behavior.
5. On an uncorrected page, zone preset/custom applies and the dialog info line are
   byte-for-byte today's behavior; page-scale applies are untouched in all cases.
6. Editing a corrected zone and re-applying a preset yields the same value (no factor
   compounding). Ctrl+Z after a zone apply restores the prior zone scale.
7. Signed in with Supabase enabled, every zone apply fires `scale_set` with
   `{target:'zone', method, pixelsPerUnit, unit, correctionFactor, pageIndex, edit}`;
   with Supabase disabled or signed out the flows work identically with no errors.
8. `npm run check` passes (including build:guides and build:sw staleness checks); `npx
   playwright test scale.spec.js` passes including the four new cases;
   ARCHITECTURE/FEATURES/FEATURE-CATALOG rows, the scale.js header comment, and the
   scale-zones guide reflect the new behavior.
