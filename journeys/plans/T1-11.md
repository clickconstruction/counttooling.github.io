# T1-11 — Choose-tab count badges: sum across canvases

Plan of record for Tier-1 item #11 in JOURNEY-MAP.md ("Ranked improvement shortlist", row 11,
currently JOURNEY-MAP.md:199). Source dossier: journeys/count-fixtures.md, finding 11
(dossier line ~67; verification note at line ~188). Effort: S. Telemetry column: none.

## Problem (verified)

The Counter modal's Choose tab shows a per-counter count badge that **always reads 0**,
no matter how many marks are placed. `populateCounterChooseList` in
[features/counter.js:64](../../features/counter.js) computes:

```js
const count = state.pages.reduce((n, p) => n + ((p.annotations?.counterMarkers?.[c.id] || []).length), 0);
```

`p.annotations` is dead data: since the canvas-layers refactor, marks live in
`p.canvases[].annotations`, and [annotation-model.js:91-97](../../annotation-model.js)
(`migratePageToCanvases`) **deletes `page.annotations`** in every migration path — so the
reduce is structurally always 0. The correct-summing paths prove the contrast on the same
screen: the sidebar badge ([features/sidebar-lists.js:47](../../features/sidebar-lists.js))
sums via `App.getActiveAnnotations(p, pi)` and reads correctly.

Repro from the dossier (journeys/count-fixtures.md, finding 11 + Verification-notes):
place marks (e.g. 7 Water Closet / 4 "90" / 2 Cleanout), open the Counter modal (C or
`#counterBtn`) — sidebar reads 7/4/2, Choose rows read 0/0/0
(img/count-fixtures-10.png). Re-driven with 3 marks: Choose badges 0/0, sidebar 3/0, and a
canvases-aware recount over the same state returned [3, 0]. Severity: a lying number in
the daily-core flow (J4 count-fixtures) — an estimator who trusts it re-counts a sheet;
one who doesn't stops trusting every number in the app.

## Design

**One line changes.** In `populateCounterChooseList`
([features/counter.js:64](../../features/counter.js)), replace the dead
`p.annotations` reduce with the merged-across-canvases helper that already exists and is
already published on the registry (`App.getMergedAnnotationsForPage`, published at
app.js:6315; core in [annotation-model.js:71](../../annotation-model.js)):

```js
const count = state.pages.reduce((n, p) => n + ((App.getMergedAnnotationsForPage(p)?.counterMarkers?.[c.id] || []).length), 0);
```

Why merged-all-canvases (not active-canvas like the sidebar): the shortlist row is titled
"sum across canvases" and the Choose picker answers a project-scoped question — "how many
of this counter have I placed anywhere in this bid" — not a per-layer view. Call with NO
second argument: `getMergedAnnotationsForPage(page)` with `onlyIds` omitted is the classic
merge-everything path (the array-gated `onlyIds` filter is the show-canvases peek and must
not be involved here; see the comment at annotation-model.js:65-70).

House-conventions check (AGENTS.md "window.App registry"): the feature file already reads
its deps from `App.*` at call time inside the function — this edit follows the same
pattern, and `getMergedAnnotationsForPage` is already on `App`, so **no new registry
publish is needed** in app.js.

**What does NOT change:**

- The sidebar badge (`sidebar-lists.js:47`, active-canvas sum) and the Summary list
  (`summary-list.js`, zone-multiplied) — harmonizing raw/multiplied/per-layer arithmetic
  app-wide is Tier-2 item #24, out of scope here.
- The Choose row markup, click handler, search filter, empty states, Create/Quick tabs —
  untouched.
- annotation-model.js, app.js, the registry block — untouched.
- No new helper, no extraction: the fix reuses an existing published function.

**Simplicity budget:** removes the last consumer of the dead pre-refactor `p.annotations`
read in features/counter.js — one lying number deleted, zero new surface, net ±0 lines.

## Risks & edge cases

- **Divergence from the sidebar on multi-layer pages:** the sidebar sums the active
  canvas only (`sidebar-lists.js:47`); after this fix the Choose badge sums ALL canvases.
  On a page with marks on a non-active layer, Choose ≥ sidebar. This is the shortlist's
  chosen semantics (project total in the picker) and the common case (one canvas per
  page) is identical — but flag it in the PR description and cross-reference **Tier-2
  #24** (one arithmetic everywhere), which is the item that reconciles raw/multiplied/
  per-layer displays; do not partially implement #24 here.
- **Zone multiplication:** the badge stays a RAW placed-marks count (like the sidebar
  today), not the zone-multiplied Summary number — also #24's territory.
- **Peek filter leakage:** passing a page index or the peek's `onlyIds` array by mistake
  would silently narrow the sum; the call must be `getMergedAnnotationsForPage(p)` with
  one argument (the model treats non-array second args as merge-everything, but don't
  rely on it).
- **Perf:** `mergeAnnotations` allocates per page per counter row (pages × counters calls
  on each modal open/keystroke of the search box). For realistic sets (≤200 pages, tens
  of counters) this is a modal-open path, not a render loop — acceptable; do NOT add a
  cache in this PR.
- **Interaction with T2 #17 (counter-create ergonomics, counter.js:59/:86/:113/:164):**
  touches the same file. Keep this PR to line 64 + spec + docs so the two merge cleanly.
- **Legacy projects:** a page that somehow still carries `p.annotations` without
  `canvases` is handled — `getPageCanvases`/migration paths normalize before merge, and
  every load path runs the migration (dossier verification note).

## Acceptance criteria

1. With marks placed on multiple counters and multiple pages, opening the Counter modal's
   Choose tab shows per-counter badges equal to the total placed marks of that counter
   across ALL pages and ALL canvases (repro state 7/4/2 shows 7/4/2, not 0/0/0).
2. A mark on a non-active canvas layer is included in the badge (verifiable via the new
   spec step or manually: add a layer, place a mark, switch back, open Choose).
3. The badge live-updates on reopen after undo (Ctrl+Z retracting a mark drops the badge
   by 1 next time the list is populated — no caching added).
4. Search-filtered Choose rows show the same correct counts (the reduce runs per filtered
   row, unchanged path).
5. `git diff features/counter.js` is a one-line change at the old line 64; no other
   runtime file changes except the generated sw.js `CACHE_VERSION` restamp.
6. `npx playwright test counter.spec.js` passes with the new across-canvases assertion;
   `npm run check` passes (including `build:sw -- --check`).
7. ARCHITECTURE.md rows for features/counter.js and counter.spec.js mention the new
   behavior; no FEATURES/FEATURE-CATALOG or guide edits are present.
