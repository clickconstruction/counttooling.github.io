## Problem (verified)

"Clear Page" has no visible control at any width. The header `#clearPage`
(app/index.html:177) carries `replaced-by-status-bar`, killed by
`.header .replaced-by-status-bar { display: none !important; }` (styles.css:541)
— but unlike its siblings (Export/Import/Sign In…) it never got a status-bar
replacement (no Clear element exists in `#statusBarActions`; ARCHITECTURE.md:853
documents one that isn't there). The sidebar `#clearPageSidebar`
(index.html:408, last sidebar section `.sidebar-clear-page`) gets mobile
`display: block` at styles.css:206 but the later unconditional
`.sidebar-clear-page { display: none; }` at **styles.css:439** wins at every
width (same specificity, later in file — media query irrelevant). The only live
route is Project Settings → Clear Page (app.js:3996), and signed out on desktop
the gear opens Sign In instead — a purely local action gated behind cloud login.
Verifier scope note: at ≤768px the drawer gear `#sidebarLogoGear` reaches
Project Settings (and Clear Page) WITHOUT sign-in — **desktop signed-out is the
gated case**. Everything behind the buttons already works: the click handlers
are live (features/import-clear.js:91-92), the confirm modal, undo snapshot,
and viewer gating (app.js:2261-2266 inline-hides `clearPageSidebar` for
viewers, resets to `''` otherwise) all ship today.

## Design

**One file: `styles.css`. CSS-only; zero JS, zero HTML.**

1. **Delete styles.css:439** `.sidebar-clear-page { display: none; }` — the
   kill. A `<div>` defaults to block, so the section renders at all widths.
2. **Delete styles.css:206** `.sidebar-clear-page { display: block; }` (inside
   the ≤768px block at :166) — redundant once :439 is gone.
3. **Delete styles.css:205** `.header #clearPage { display: none; }` — redundant
   with the unconditional `!important` kill at :541 (which stays; safe only
   while :541 stays — they're a pair).
4. **Add one rule** beside the existing has-pdf pattern at :455
   (`body:not(.has-pdf) .canvas-switcher { display: none; }`):
   `body:not(.has-pdf) .sidebar-clear-page { display: none; }` — no danger
   button when there is nothing to clear, mirroring the Project Settings row's
   `state.pages.length > 0` gate (app.js:2444).

Net: −3 rules, +1 rule.

**What does NOT change:** the header `#clearPage` element and the :541 family
kill (it stays dead alongside Export/Import — no second visible entry);
the Project Settings row; the drawer-gear mobile path; features/import-clear.js;
the button label ("Clear Page", matching the modal heading and settings row);
the confirm wording "Clear current canvas (Main)?" — that's the separate
fix-mistakes *polish* item (with its layer-scope caveat) and is NOT this PR;
viewer gating; undo behavior.

**Simplicity budget** (spirit test #3): deletes two dead/redundant CSS rules
plus the kill itself; removes the sign-in dependency for a local action
(4 gated steps → 2 visible ones); adds no new surface — it un-hides a button,
handler, and confirm flow that already exist. Findable (#4): the sidebar is
where the unguided walker hunted first.
