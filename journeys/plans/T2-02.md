# T2-02 — Polyline Esc staged like Quick Line

Plan of record for Tier-2 item #22 (JOURNEY-MAP.md "Tier 2" row 22; Stage-2

4 clicked vertices + one Esc → 0 polylines committed, tool back to Move; Quick
Line's staged Esc reproduced in the same session). Proposal verified for the
**staged-Esc form only** — the dossier explicitly killed the confirm-dialog

## Problem (verified)

The global Escape ladder (app.js keydown, `// SECTION:` hotkeys area) handles a
mid-draw polyline in one unstaged branch — app.js:6339:
`else if (state.drawingPolyline) { state.drawingPolyline = null; state.tool = TOOL.NONE; updateUI(); }`
— discarding every clicked vertex at once. The sibling tools all stage:
Quick Line (app.js:6340-6342, first Esc clears `quickLineStart`, second exits),
Chain/Highlight ladders (:6343-6348, :6371-6376), every zone tool, and Ghost —
whose comment (features/ghost.js:91-92) names the rule this branch violates:
"Escape unwinds one step at a time (the Quick Line convention), so a stray
Escape never throws away more than the user's last click." A stray Esc fifteen
vertices into a waste main erases the whole trace, unrecoverably (vertices are
pre-commit scratch state — `finishPolyline` app.js:3771 is the only writer into
`annotations.polylines`, so undo can't bring them back).

## Design

One branch edit in the Escape ladder (app.js:6339). Keep its position — after
the `TOOL.EDIT_POLY` branch (:6338), before `TOOL.LINE` — and keep it keyed on
`state.drawingPolyline` alone (tool-independent, as today):

```js
else if (state.drawingPolyline) {
  // Staged like Quick Line/Ghost: each Escape unwinds one clicked vertex;
  // with none left, Escape exits to Move. A stray Esc never costs more
  // than the last click. (JOURNEY-MAP Tier-2 #22)
  if (state.drawingPolyline.points.length > 0) { state.drawingPolyline.points.pop(); renderAnnotations(); updateUI(); }
  else { state.drawingPolyline = null; state.tool = TOOL.NONE; updateUI(); }
}
```

Semantics call: the shortlist's "first removes the last vertex, second exits"
is Quick Line's wording, where one pending click is the maximum. The faithful
generalization is **per-vertex unwind, then exit** (the Ghost precedent,
verbatim) — a literal "second always exits" would still nuke 14 vertices on a
double-tap Esc, the exact work-loss this item exists to kill. Deliberate
abandon stays one gesture: M / the Move button (`moveReset`, app.js:6178)
discards the whole draft instantly, unchanged.

**Why it just works:** `renderAnnotations` repaints the dashed in-progress
preview from `state.drawingPolyline.points` (app.js:1922-1926); `updateUI`
keys the `#polylineFinishBar` on `!!state.drawingPolyline` (:2252) so
Finish/Close Polygon stay up through pops; Enter-finish (:6433), dblclick
(:5153), right-click close (:5187) all key on `points.length` and degrade
correctly as vertices shrink below 2/3; 45° snap re-anchors on the new last
vertex (:4879-4887). No new state, no new UI, no undo snapshots (pre-commit
scratch, same as Quick Line/Ghost).

**What does NOT change:** `finishPolyline` (:3771-3784); the polyline modal +
Start (:3756-3766); `TOOL.EDIT_POLY` Esc (`exitEditMode(false)`, :6338); the
tool-switch and `moveReset` wholesale clears (:2249, :3412, :6178); the T1-05
page-switch disarm (:1285-1300 — leaves `drawingPolyline` set with tool NONE;
the branch's tool-independence keeps that draft Esc-poppable and
Enter-finishable, as today); the modal-close ladder above the branch; touch
flows (no Esc key); `HOTKEYS`/Macros (Esc is not a HOTKEYS entry — no
build:macros).

**Simplicity budget:** removes the last divergent Esc model — one convention
across all eight staged tools instead of seven-plus-an-exception; removes the
catastrophic re-trace class; makes the dossier's confirm-dialog alternative
permanently unnecessary. Adds zero surface: net +3 lines inside one existing
branch.

## Risks & edge cases

- **Zero-vertex draft** (Start Drawing, then Esc): pops nothing → exits, one
  press — byte-identical to today.
- **Tier-2 #15 (toast rework)**: a visible toast is a modal that eats the Esc
  before the ladder reaches the tool (app.js:6251-6264 comment) — pre-existing,
  identical for Quick Line, and #15's fix un-eats it for free. No coupling.
- **Tier-2 #28 (polyline dialog tax)** restructures the modal/arm path; #20
  (create-arms-the-tool) wires `#polylineNewLineType`; #21 edits the footer
  hint (status-bar.js:166). None touch the Escape ladder — no conflict, any
  order.
- **Shipped T1-05 page-switch disarm** leaves an orphan draft (tool NONE,
  `drawingPolyline` set). Today one Esc silently deletes it; after this change
  Esc unwinds it — strictly safer, and Enter/M behave as before.
- **EDIT_POLY** precedes in the ladder; committed-polyline vertex editing
  (right-click delete, :5175-5185) is a different mode — untouched.

## Acceptance criteria

1. Draw 5 polyline vertices, press Esc once: the newest vertex and its dashed
   leg disappear, the tool stays armed, the finish bar stays up, and the next
   click re-adds a vertex snapped against the new last point.
2. Esc pressed 6 times from those 5 vertices: vertices unwind one per press,
   then the tool drops to Move; nothing was committed and no console error.
3. Enter after any number of pops commits exactly the remaining vertices
   (≥2); right-click close-polygon still needs ≥3.
4. With any modal or toast visible mid-draw, Esc closes it and pops nothing.
5. Quick Line, Chain, Highlight, zones, and Ghost Esc behavior byte-identical
   to today; M still abandons a draft in one press.
6. `npm run check` passes (incl. build:guides/build:sw freshness);
   `polyline-esc.spec.js` green.
