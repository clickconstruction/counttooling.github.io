## Problem (verified)

Every toast in the app is a full-screen modal overlay. The four toast surfaces
— `#setScaleFirstModal` (app/index.html:1199), `#outOfBoundsModal` (:1204),
`#pipeToolingCopiedModal` (:1209), `#airboardToastModal` (:1246) — are
`.modal-overlay` divs: `position:fixed; inset:0; background:rgba(0,0,0,0.6);
z-index:200` (styles.css:542). Three verified consequences:

1. **Toasts swallow clicks app-wide.** During any toast, `elementFromPoint` at
   canvas center returns the toast (J3 re-drive); clicks die silently for the
   toast's lifetime. Worst cases: the 2s "Scale set — verify it against a known
   dimension" toast appears exactly when the user should click the plan to
   verify (J3 — two verify picks eaten), and the 5s `Distance:` result toast
   (app.js:4911, `showToast('Distance: …', 5000)`) eats the first Scale Zone
   corner click at the measure→zone hand-off — the exact order J6 runs in.
   Clicking a toast does not dismiss it.
2. **Toasts paint UNDER equal-z-index modals.** `airboardToastModal` sits
   before `roomBoxModal` in the DOM at the same z-index 200, so the Room Sizer
   empty-ceiling-height rejection ("Enter a ceiling height (e.g. 9.5 or
   9'6)." — features/room-sizer.js:248) renders invisibly behind the open
   dialog. J7 Friction #4: reads as a broken Apply button. This hides toasts
   behind every tall modal, not just roomBoxModal.
3. **The modal nature leaks into the keyboard path.** The Escape ladder closes
   toasts before tools (app.js:6271 setScaleFirstModal, :6274 outOfBoundsModal,
   plus a pipeToolingCopiedModal entry), which forced the Ghost-gesture
   pre-clear hack at app.js:6252-6264 — whose own comment says "Retire this
   with the queued non-blocking-toast work (JOURNEY-MAP Tier-2 #15)".

This obstructed three Tier-1 builds; ~13 spec files wait toasts out or hide
them manually (`grep -l "airboardToast\|setScaleFirstModal" *.spec.js`).

## Design

One principle, three parts: **(1)** toasts become passive corner cards in one
stacked region that paints above every modal and blocks nothing; **(2)** the
one deliberate blocking state (turn-in progress) stops masquerading as a toast;
**(3)** the `Distance:` result moves off the canvas into a footer chip.

### Part 1 — the toast region (app/index.html + styles.css)

**app/index.html** — add one container near the end of the overlay block and
move the four toast elements into it, collapsing their two-layer
overlay>card markup to a single card each. Ids stay on the element that gets
`.visible` (so `showModal`/`hideModal` — which only toggle that class by id,
app.js:2749 — and every spec selector keep working). Inner `<p>` ids
(`#airboardToastText`, `#setScaleFirstText`, `#pipeToolingCopiedDetail`) and
their inline styles (pre-line etc.) are untouched:

```html
<div id="toastRegion" role="status" aria-live="polite">
  <div class="toast-card" id="setScaleFirstModal"><p id="setScaleFirstText" …></p></div>
  <div class="toast-card" id="outOfBoundsModal"><p …>Click inside the page to place.</p></div>
  <div class="toast-card" id="pipeToolingCopiedModal">…(both existing <p>s)…</div>
  <div class="toast-card" id="airboardToastModal"><p id="airboardToastText" …></p></div>
</div>
```

Also add the turn-in overlay Part 2 needs, using today's exact toast-card
markup shape: `<div class="modal-overlay" id="turnInProgressModal"><div
class="modal-card modal-card-toast"><p id="turnInProgressText" …></p></div></div>`
(keeps the `.modal-card-toast` rule at styles.css:871 alive with one user).

**styles.css** — next to the modal styles, with a comment stating the z-order
contract (modals 200-260 < menus/panels 300 < toasts 350 < header-more-menu /
view-link-dead 400):

```css
#toastRegion { position: fixed; top: calc(52px + var(--safe-top) + 12px);
  right: 12px; z-index: 350; display: flex; flex-direction: column;
  align-items: flex-end; gap: 8px; pointer-events: none;
  max-width: min(400px, calc(100vw - 24px)); }
.toast-card { display: none; background: var(--surface);
  border: 1px solid var(--border2); border-radius: 8px; padding: 12px 16px;
  box-shadow: 0 8px 24px rgba(0,0,0,0.45); }
.toast-card.visible { display: block; }
/* T2-06 hook: a card that carries a real control opts back into clicks. */
.toast-card.toast-interactive { pointer-events: auto; }
```

`pointer-events: none` on the region covers every card (per the verified J3
proposal); `.toast-interactive` is the named opt-in T2-06 (#23, the scale-gate
toast→link) will use — do NOT build the link itself here. Stacking is honest
by construction: distinct simultaneous toasts (each element keeps its own
timer) flex-stack instead of painting over each other, and z-index 350 ends
the under-modal occlusion (roomBoxModal at 200, `#lineColorModal` at 260 —
both below). Update the two comments that assert the old order:
styles.css:545 (view-link-dead "above .modal-overlay/toasts (200)") and :1284
(zoom-rail vs toasts).

### Part 2 — app.js

- **`setTurnInProgress` (app.js:2781)** targets the new `#turnInProgressModal`
  / `#turnInProgressText` and drops its `airboardToastTimer` clearing (it no
  longer shares an element with `showToast`). Turn-in stays a deliberate
  blocking overlay — it is a save/checkout progress state, not a toast. Its
  callers (features/turn-in.js:166/:171, the save-engine ctx entry at
  app.js:473, registry publish at :6814) are shape-unchanged.
- **Escape ladder**: delete the Ghost pre-clear block (app.js:6252-6264 — its
  comment names this work) and the three toast entries (setScaleFirstModal
  :6271-6273, outOfBoundsModal :6274-6276, and the pipeToolingCopiedModal
  entry further down). Non-blocking toasts self-dismiss and block nothing, so
  Escape falls through to real modals/tools — the two-press rhythm the Ghost
  hack existed to protect now needs no hack.
- **Distance readout** (app.js:4911, measure completion): replace
  `showToast('Distance: ' + formatted, 5000)` with
  `state.lastMeasure = { text: 'Distance: ' + formatted, pageIdx: state.currentPage };`
  — in-memory only (like `state.localPdfHash`; NOT persisted, NOT in
  save/load). No clearing hooks needed: the chip renders only while
  `lastMeasure.pageIdx === state.currentPage` (page flips hide it, returning
  to the sheet shows it again — it is a fact about that sheet), a new measure
  overwrites it, and a PDF/project load resets state.

`showToast` itself (app.js:2772) is UNCHANGED — same signature, same
single-slot last-toast-wins semantics, same timers. All ~60 call sites across
app.js and features (undo count, filter toasts, tool-context-menu
"No settings", append "Added N sheets", room-sizer errors, view-link copy…)
ship unmodified; the fix is entirely in where the element lives and paints.

### Part 3 — the footer Distance chip (features/status-bar.js + app/index.html)

Add `<span id="statusMeasure" class="status-totals" style="display:none;"></span>`
beside `#statusTotals` (app/index.html:479). In `updateStatus`
(features/status-bar.js, beside the `#statusTotals` render at :203-217): show
`App.state.lastMeasure.text` when set and on the current page, else
`display:none`. Trade-plain, zero new chrome — the footer already coaches
("Tap second point") and already carries totals. T2 #21 (live length while
drawing) later rides the *hint* slot; this chip is a separate span, no
collision.

**What does NOT change:** `showToast` / `showSetScaleFirstToast` /
`showOutOfBoundsToast` APIs and every call site; all toast copy and durations
(2s default, 3s gate, 4s overlap warnings, 1.5/2.6s copied); real modals and
the `.modal-overlay` rule; `hideModal`'s feature callbacks;
features/output.js's copied-modal show/hide timers (:110, :285-286);
features/room-sizer.js (its :248 error simply becomes visible); the T1-05
page-switch scale gate (app.js:1319) and its toast wording; turn-in blocking
behavior; specs' `#airboardToastText` text assertions.

**Simplicity budget** (spirit test #3): removes the click-swallowing overlay
behavior from all four toast surfaces in one place with zero per-call-site
edits; deletes the Ghost Escape pre-clear hack and three Escape-ladder
entries; removes the 5s `Distance:` canvas blackout and with it the whole
phantom-click failure mode at the measure→zone hand-off; makes the room-height
validation the app already ships actually visible instead of adding new modal
UX; builds no toast framework (no queue, no animation, single-slot semantics
kept — stacking falls out of a flex column). Nothing new is added except one
container div, one chip span, and the turn-in overlay that replaces a shared
element. Spirit #1: fewer redone steps (no eaten clicks, no forced 2s pauses);
#2: no new words; #4: n/a — it stops hiding things.

## Tests

House naming: `*.spec.js` = Playwright, `*.test.js` = Node unit. **No Node
unit tests** — no pure module changes (this is DOM/CSS/z-order work).

**New `toast-region.spec.js`** (owns the toast-system contract — no existing
spec does):
1. Non-blocking: fire `App.showToast('x', 3000)`; `elementFromPoint` at canvas
   center returns the annotation canvas, and a real canvas click during the
   toast places a counter mark.
2. Above modals: open a tall modal (roomBoxModal or counterModal), fire a
   toast; `elementFromPoint` at the toast's center returns the toast text, not
   the modal.
3. Honest stacking: make `#outOfBoundsModal` and `#airboardToastModal` visible
   together; both visible, boundingBoxes do not intersect.
4. `#toastRegion` computed `pointer-events` is `none`; a plain `.toast-card`
   inherits it; a card given `toast-interactive` computes `auto` (the T2-06
   hook).
5. Escape: with a toast visible and `scaleModal` open, one Escape closes
   scaleModal (the toast no longer eats it) and the toast still self-dismisses.

**Extend owning specs:**
- `room-sizer.spec.js`: Apply with empty ceiling height → the "Enter a ceiling
  height" toast is visible ABOVE the still-open roomBoxModal
  (`elementFromPoint` check) — the J7 occlusion regression.
- `scale.spec.js`: while the post-apply "Scale set — verify…" toast is up, two
  immediate canvas clicks register (arm Scale Zone; first corner commits) —
  the J3/J6 eaten-click regression.
- `footer-hint.spec.js` (owns status-bar composition): complete a Measure →
  `#statusMeasure` reads `Distance: …`; still shown after 6s (outlives the old
  5s toast, and `#airboardToastText` never contained "Distance"); page flip
  hides it; flipping back shows it; a new measure replaces it.
- Existing toast-adjacent specs (drop-mode, ghost, undo-toast, output,
  pdf-upload, prepare-pdf, quick-keys, scale-gate-page-switch, scale-zone-tool,
  sidebar-usage-filter, tool-context-menu) keep passing unmodified — their
  visibility waits still resolve and text assertions still hold. Do not
  proactively rewrite their now-redundant wait-out-the-toast steps; update
  only what fails.

## Risks & edge cases

- **T2-06 (#23) depends on this**: the scale-gate toast becomes a link INSIDE
  a `pointer-events:none` card — that is exactly what `.toast-interactive` is
  for. Land T2-04 first; T2-06 then adds the class + link markup + handler and
  lengthens that one toast's timer 3s→6s (deliberately superseding this plan's
  "durations unchanged" stance for the gate toast only).
- **T2-02 (polyline Esc staging)** edits the same Escape-ladder region this
  plan deletes entries from (its branch sits below the modal-close rungs).
  Rebase carefully; no logic overlap — T2-04 removes rungs above, T2-02 adds
  one below.
- **Shipped Tier-1 behavior**: T1-05's `scale-gate-page-switch.spec.js` waits
  on `#setScaleFirstModal.visible` — preserved (same id, same class). The
  T1-08 append toast text assertions (`pdf-upload`/`prepare-pdf` specs) are
  text-only — preserved. The gate toast turning non-blocking is strictly
  better for T1-05's disarm flow (nothing to wait out before re-arming).
- **Turn-in must keep blocking**: it guards a save+checkout-release in flight.
  Verified the only writers are features/turn-in.js and the save-engine ctx;
  both go through `setTurnInProgress`, which this plan re-points wholesale. A
  live toast can now paint over the turn-in overlay (350 > 200) — harmless,
  it blocks nothing.
- **Ghost flow**: toasts after every capture step are now non-blocking, and
  Escape is never eaten by them — the deleted hack's spec coverage
  (ghost.spec.js; its :227 manual hide stays valid) must pass unmodified.
- **Corner placement**: top-right under the header overlaps the mobile
  zoom-rail (z 300, right edge) — toasts paint over it for a few seconds but
  never block it (`pointer-events:none`). Accepted; revisit placement only if
  field feedback says so.
- **Discoverability trade**: corner cards are less in-your-face than a dimmed
  center card. Copy and durations are unchanged; the one toast whose noticing
  really matters (set-scale-first) gets the T2-06 link follow-up, and the
  `aria-live="polite"` region announces toasts to screen readers (new, benign).
- **Mobile modal rule**: `.modal-overlay.visible .modal-card { max-height:85vh }`
  (styles.css:271) no longer applies to toast cards — the region's
  `max-width: calc(100vw - 24px)` plus pre-line text keeps them on-screen;
  eyeball the long overlap-warning toast at 375px width.
- **`state.lastMeasure`** is deliberately not persisted and not cleared on
  tool change — it is a per-sheet fact, hidden off-sheet by the render
  condition. If a stale reading after re-scaling a page proves confusing in
  bake-in, clear it in `setPageScale` (one line, follow-up).

## Acceptance criteria

1. During ANY toast, the canvas keeps taking clicks: after a preset scale
   apply, two immediate verify/zone clicks both register; nothing dims.
2. Room Sizer Apply with an empty ceiling height shows "Enter a ceiling
   height (e.g. 9.5 or 9'6)." visibly above the open dialog.
3. Two simultaneous toasts stack vertically in the corner without overlap;
   each dismisses on its own timer.
4. Measure result appears as a footer chip (`Distance: 25'-0"`), persists
   while you keep working on that sheet, hides on page flip, returns when you
   flip back; no `Distance:` toast fires; arming Scale Zone immediately after
   measuring loses zero clicks.
5. Escape with only a toast on screen reaches the tool/modal ladder (toasts
   never consume it); the Ghost pre-clear block is gone from app.js.
6. Turn-in progress ("Turn In: …") still blocks the app until it clears.
7. Header, menus, zoom rail, and the view-link-dead screen keep their
   interaction behavior (toasts paint above modals/menus, below the dead
   screen, and block none of them).
8. `npm run check` passes; the full Playwright suite passes locally with no
   changes to the 13 existing toast-adjacent spec files beyond what failure
   forces (expected: none).
