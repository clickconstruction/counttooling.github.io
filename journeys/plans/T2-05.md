## Problem (verified)

Three confirmed stumbles on the single highest-traffic surface (counting is now
the broadest daily activity — 622 marks/8 users in the 20-day telemetry window),
all inside `#counterModal` + its upload input:

1. **Create ergonomics fork (#17).** `#counterBtn` (C hotkey, sidebar,
   mobile drawer via `#counterBtnSidebar`) always lands on the Choose tab with
   the name cleared (counter.js:83-86) — on a fresh project that is an empty
   state whose copy names an off-screen button ("Add a counter first using
   Create Counter." — counter.js:59; the button only exists after switching
   tabs, J1 #5). The `#addCounter` "+ Add" path prefills
   `getIconName(icons[0].value)` **unconditionally** (counter.js:113) — with
   "Water Closet" already in the palette, two bare clicks mint an identical
   twin (same name/icon/`#e8c547`) that silently splits the tally (J4 #13,
   re-driven). And a blank-name create falls back to the literal string
   `'Counter'` (counter.js:164 `value.trim() || 'Counter'`) with no numbering,
   so repeat blanks collide under one name (J1 #2). The C-route also never
   populates the custom-icon grid — the two openers are a behavioral fork of
   the same panel.
2. **Icon search shipped hidden (#18).** `#counterIconSearchGroup` carries an
   inline `style="display:none"` (app/index.html:612) that nothing toggles;
   the `#counterIconSearch` input handler at counter.js:145 is live and
   unreachable. Users scroll a ~250-cell grid; `custom-icons.md` promises a
   search that never appears (J4 #4).
3. **Upload success is invisible (#19).** A successful custom-SVG upload
   appends the icon selected-but-below the 200px grid fold (cell ~308px down,
   `scrollTop` 0) with no scroll and no toast — the modal is pixel-identical
   before/after and reads as a no-op, inviting re-uploads (J4 #12;
   features/custom-icon-upload.js:63-122 has no scrollIntoView).

## Design

One branch, three commits (same modal surface). **Simplicity budget,
stated:** commit 1 *deletes* the two-opener behavioral fork (one shared
create-panel prep), *deletes* the `|| 'Counter'` fallback path, and removes
the rename-and-merge cleanup twins force later; commit 2 is a net deletion of
dead surface (an inline attribute) that also makes an existing guide truthful
with zero doc edits; commit 3 adds no chrome — pure feedback on an element
that already exists. No new modals, no new buttons, no new words beyond one
reworded empty-state line. (Spirit test: fewer steps on the first-counter
path; "Water Closet"/"Lavatory" trade names instead of "Counter"; all three
changes are findable by construction — they happen to you.)

### Commit 1 — create ergonomics (#17), `features/counter.js` + two copy strings

Extract the `#addCounter` handler body (counter.js:109-142, minus
`App.showModal`) into a private `prepCreatePanel()` and make BOTH openers call
it — this is the fork deletion:

- `#addCounter.onclick` → `prepCreatePanel(); App.showModal('counterModal');`
  (behavior identical except the smarter prefill below).
- `#counterBtn.onclick` → reset `#counterModalSearchInput`; call
  `prepCreatePanel()` (replaces lines 86-92: the name-clear, icon-search
  clear, built-in-grid-only rebuild, and the duplicate
  `setupCreateColorPicker` call — all now owned by the shared prep); then
  `if (App.state.counters.length === 0) showCounterTab('create')` else the
  existing choose path (`showCounterTab('choose')` + list + focus). So C on a
  fresh project lands on Create, prefilled — exactly like + Add — and a
  manual Choose→Create tab switch shows a fully prepped panel (custom grid
  included) instead of a blank name.
- **Prefill the next unused library icon's name** inside `prepCreatePanel()`:
  build a Set of existing counter names (trimmed, lowercased); `prefillIdx` =
  first index in `App.getOrderedIcons()` whose `App.getIconName(value)` is
  not in the set (fallback 0 when all are used); set `#counterName` to that
  icon's name and select that cell
  (`iconGridCellsHtml(icons, iconVbFor, (ic, i) => i === prefillIdx)`) so the
  name matches the visible selection. Respects the user's `iconOrder`.
- **Twin guard** in the `#counterCreate` handler (counter.js:162-180):
  compute `icon` first, then
  `const name = counterName.value.trim() || App.getIconName(icon);` — the
  `|| 'Counter'` literal is deleted. Then, if an existing counter has the
  same trimmed name (case-insensitive): append the lowest free numbered
  suffix (`"Water Closet 2"`, `" 3"`, …), and **only when that twin also has
  the identical icon AND color**, rotate the color to the first `App.COLORS`
  entry no counter uses (fallback: next index after the chosen color). A
  deliberate same-name/different-color counter keeps its chosen color and
  just gets the suffix — no legit workflow blocked, no dialog.
- **Empty-state reword** (now reachable only by manually switching to
  Choose): counter.js:59 zero-counter branch and the static default at
  app/index.html:640 both become
  `"No counters yet — use the Create tab above."` The search-miss branch
  ("No counters match…") is untouched.

### Commit 2 — un-hide the icon search (#18), `app/index.html` + 1 line in counter.js

Delete the inline `style="display:none;"` from `#counterIconSearchGroup`
(app/index.html:612). One guard so we don't mint a new J4-#8-style inert
search box: the group sits above BOTH icon panels but the live handler filters
only the built-in grid, so add one line to `showCounterIconTab()`
(counter.js:41-48): the group shows only when the "Icon" tab is active. The
counter.js:145 handler is already correct (filters by `terms`, keeps a custom
selection, rewires cell clicks) — untouched.

### Commit 3 — visible upload (#19), `features/custom-icon-upload.js` + `styles.css`

In `selectUploadedIcon()` (custom-icon-upload.js:54-61), after
`cell.classList.add('selected')`: `cell.scrollIntoView({ block: 'nearest' })`
and add a `flash-new` class. This one function serves all three surfaces
(Create Counter, Quick Count, Details grids), so the fix lands once. In
styles.css add `.icon-cell.flash-new` — a short (~1.2s) keyframe pulse of the
existing selection-ring color, `animation-iteration-count: 1`; no JS removal
listener needed (each upload rebuilds the grid via `innerHTML`, so the class
never survives to a later render). No toast — the scroll + flash IS the
feedback (J4 proposal: "pure feedback", verified spiritPass).

### What does NOT change

The Choose tab's pick flow and its (already-fixed) count badges; the Quick
Count tab and its create path (features/quick-modals.js:223 — that is T2 #16's
surface); `showCounterTab`'s tab mechanics and the Shift+Q entry
(app.js:6198); the modal-level "Search counters…" box (J4 #8 is a `hide`
batch item, not this unit); mid-open tab flips still never re-populate (icon
selection persists — prep runs at open time only, and prefill overwrites
nothing the user typed because both openers run prep before the user can
type); the SVG parser, `refreshCustomGrid`, and the rejected-upload alert;
Esc/backdrop behavior (Tier-3 B1); all `window.*` report.js globals; no
`App.*` registry additions.

## Tests

House naming (`playwright.config.js` testMatch): `*.spec.js` = Playwright.
No pure-module edits → no new `*.test.js`. Extend the two owning specs:

- **`counter.spec.js`** (owns #counterModal):
  1. Zero counters, `#counterBtn` click → Create panel visible, `#counterName`
     equals icon[0]'s name, that grid cell `.selected`, custom grid populated.
  2. With a counter named after icon[0] already in `state.counters`,
     `#addCounter` → prefill equals icon[1]'s name and icon[1]'s cell is
     selected (next-unused walk).
  3. Twin guard: create the prefilled counter twice, changing nothing → second
     is `"<name> 2"` with a color ≠ the first's; create a same-name but
     different-color counter → suffix applied, chosen color kept.
  4. Clear `#counterName`, Create → counter named after the selected icon; the
     string `"Counter"` appears in no `state.counters[].name`.
  5. `#counterIconSearchGroup` visible on the Icon tab and hidden on the
     Custom Icons tab; typing `water` into `#counterIconSearch` shrinks the
     built-in grid's cell count and the first match is selected.
  6. Choose-tab empty state (zero counters, manual tab switch) shows the new
     copy verbatim.
  (Existing tests hold: they `.fill()` their own names, which replaces the
  prefill.)
- **`custom-icon-upload.spec.js`** (owns the upload path): after the existing
  GOOD_SVG upload, assert the new cell is inside the grid's visible scroll
  window (`cell.offsetTop` within `grid.scrollTop … + clientHeight` — the
  pre-fix state was offsetTop ~308 vs clientHeight 200 at scrollTop 0) and
  carries `flash-new`.

## Risks & edge cases

- **T2 #16 (Quick Count dupes, re-rank slot 7)** owns the *other* create path
  (quick-modals.js:223) and will want this commit's color-rotate. Keep the
  twin-resolution logic a small pure-shaped private function of
  `(name, icon, color, counters)` so #16 can lift it onto `App` without
  rewriting — note this in the PR.
- **T2 #29 (Manage Icons re-home, slot 13)** may add a row to this same
  Create-tab markup — T2-05 lands first per the re-rank order; #29 rebases.
- **Tier-1 drift**: line anchors above were re-verified 2026-08-29 after the
  Tier-1 merges (the shortlist's index.html:587 → 612). Re-grep on execution.
- **Shipped fix collision**: counter.js:64 badge counting is already
  canvases-aware — leave it alone.
- **All-icons-used palette**: the prefill walk falls back to icon[0]; the twin
  guard then produces `"Water Closet 2"` + rotated color, so heavy palettes
  degrade gracefully instead of minting twins.
- **Specs that create counters programmatically** (sidebar-lists, ghost,
  palette-insights, drop-peek push into `state.counters` or `.fill()` names)
  are untouched by the prefill; the twin guard only fires on the modal's
  Create button, not on programmatic pushes.
- **Search-group toggle** must not regress the Custom tab: the handler filters
  built-ins only, hence the Icon-tab-only visibility (avoids a new inert-search
  papercut mirroring J4 #8).
- **Mobile drawer**: `#counterBtnSidebar` delegates to `#counterBtn` — the
  zero-counters Create landing applies there too; the drawer-stays-open
  stumble (J1 #3) is Tier-3 B9, deliberately not touched here.
- **Viewers**: `counterBtn`/`addCounter` are in `viewerHideIds` — no view-link
  exposure.
- **render-pixels baselines**: no canvas-drawing change anywhere in this unit
  — baselines must not move; if they do, something leaked.

## Acceptance criteria (walkable)

1. Fresh project, press **C** → Counter modal opens on the **Create** tab,
   name prefilled "Water Closet" (icon[0]), toilet cell selected, custom-icon
   grid populated; one click on Create Counter arms the tool. With "Water
   Closet" already in the palette, C / + Add prefill the next unused icon's
   name (e.g. "Lavatory") with its cell selected.
2. Creating an exact twin (same name+icon+color, changed nothing) yields
   `"Water Closet 2"` in a different color — two bare clicks can no longer
   silently split a tally. Same-name-different-color stays possible (suffix
   only). No counter can be created literally named "Counter".
3. Manually switching to the Choose tab with zero counters shows "No counters
   yet — use the Create tab above."
4. The icon search box is visible above the built-in grid; typing "drain"
   filters the ~250-cell grid live; it hides on the Custom Icons tab.
5. Uploading a valid SVG scrolls the custom grid so the new icon is visible
   and flashes its selection ring — on the Create, Quick Count, and Details
   grids alike; the "did that work?" pixel-identical state is gone.
6. `npm run check` passes; counter.spec.js and custom-icon-upload.spec.js
   extended tests pass; the full local Playwright suite passes.
