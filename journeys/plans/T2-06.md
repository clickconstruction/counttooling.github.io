## Problem (verified)

When a length tool is armed on an unscaled sheet — at arm time (app.js:3206
Measure, :3236 Quick Line, :3247 Chain, :3291 Polyline, :3323 Scale Zone,
:3359 Room Sizer, features/grid.js:52 Grid overlay) or via the T1-05
page-switch disarm (app.js:1297) — `showSetScaleFirstToast` (app.js:2796-2806)
shows "Set Scale ⚖ first to use {tool}." as plain innerHTML with an inline SVG,
self-dismissing after 3s with no handler: clicking the text does nothing
(re-driven in both dossiers). The fix it names, Set Scale, is an unlabeled
toolbar glyph the user must hover-hunt — and once a scale exists that button
hides entirely (J6 walk). The toast names the fix but makes you go find it,
36 times in 20 days.

## Design

One change: the "Set Scale ⚖" words in the toast become a real button that
opens the existing Set Scale dialog. No new words, no new surface.

- **app/index.html** (~:1199, the post-T2-04 `#setScaleFirstModal` toast
  card): add class `toast-interactive` to the card (T2-04's named opt-in —
  pointer events on this card only, the region stays `pointer-events:none`).
  Replace the empty `#setScaleFirstText` body with static markup:
  `<button type="button" id="setScaleFirstLink" class="toast-link">Set Scale
  {scale SVG}</button><span id="setScaleFirstTail"></span>` — the SVG moves
  here verbatim from app.js's `scaleIconSvgToast` string (:2795).
- **app.js** — `showSetScaleFirstToast(toolName)` stops writing innerHTML:
  set `#setScaleFirstTail.textContent = ' first to use ' + toolName + '.'`
  and lengthen this toast's timer 3000→6000ms (the J6 "~2.5s isn't enough to
  act" half of the row; a link you can't reach in time is a half-fix). Delete
  the now-unused `scaleIconSvgToast` constant. Bind once, next to the
  function: `#setScaleFirstLink.onclick` → hide the toast + clear
  `setScaleFirstToastTimer`, then `if (state.pages.length)
  App.openScaleModal(); else showToast('Open a plan first.', 2000);` — the
  exact guard tool-context-menu.js:57 already uses (registry rule: read
  `App.openScaleModal` at call time; it lives in features/scale.js:148).
- **styles.css** — one rule beside T2-04's `.toast-card` block:
  `.toast-link { background:none; border:none; padding:0; font:inherit;
  color:var(--accent); text-decoration:underline; cursor:pointer;
  display:inline-flex; align-items:center; gap:4px; }`.

**What does NOT change:** the toast wording (byte-identical textContent shape
— specs assert `setScaleFirstText.textContent` contains the tool name),
`showSetScaleFirstToast`'s signature and all 8 call sites (grid.js's
`App.showSetScaleFirstToast` included — every caller gets the link for free),
`showToast`/`showOutOfBoundsToast` and every other toast, `openScaleModal`
itself (normal page-scale mode; T1-04's verify hand-off untouched), the T1-05
disarm-to-Move behavior, and which tools are gated. The blocked tool is NOT
auto-re-armed after the scale applies — deliberate scope hold (re-arm
interacts with T1-04's verify flow and B8's zone-armed-hint item).

**Simplicity budget** (spirit test): removes the hover-hunt for an unlabeled
toolbar glyph — one tap replaces it, at the exact moment and place the user is
looking; removes the per-call innerHTML write and the JS-side SVG string
(static markup, textContent-only updates); adds zero new words (#2) and zero
new chrome — it makes seven existing words operable (#1, #4). Both dossier
proposals passed spirit review verbatim.

## Risks & edge cases

- **T2-04 ordering**: without it the link would sit inside a full-screen
  click-swallowing overlay and the Esc ladder would still target the toast.
  Sequential execution (house rule) — this plan lands only on merged T2-04.
- **6s timer vs existing specs**: room-sizer.spec.js:51, scale-gate:63-64,
  ghost.spec.js:227 hide the toast manually or catch the wait — resilient to
  the longer timer. scale-zone-tool.spec.js:39 reads visibility immediately —
  unaffected. T2-04's "durations unchanged" note is deliberately superseded
  for this one toast by this row's own auto-dismiss friction clause.
- **Interactive card blocks what's under it**: the corner card now takes
  pointer events for up to 6s over whatever it overlaps (mobile zoom-rail per
  T2-04's placement note). Small area, self-dismissing; accepted — same trade
  T2-04 pre-approved for `.toast-interactive`.
- **No-plan edge**: arm-time gates can fire with zero pages
  (`getPageScale` → null); the link's `state.pages.length` guard reuses the
  tool-context-menu fallback instead of opening a pageless scale dialog
  (B7/B8's broader no-plan gate is NOT pulled in).
- **T1-04 shipped behavior**: the link enters `openScaleModal` exactly like
  the toolbar button — preset applies with a sheet correction still flow into
  the two-point verify. No special-casing.
- **Grid overlay caller** (features/grid.js:52) shows "…to use Grid overlay."
  — the link works there too; nothing tool-specific in the handler.
- **Screen readers**: the card lives in T2-04's `aria-live="polite"` region;
  the button is announced but focus is not stolen. Benign.

## Acceptance criteria

1. Arming Quick Line (or Measure/Polyline/Chain/Scale Zone/Room Sizer/Grid)
   on an unscaled sheet shows "Set Scale ⚖ first to use {tool}." where
   "Set Scale ⚖" is visibly a link; clicking it hides the toast and opens the
   Set Scale dialog; setting the scale then lets the tool arm normally.
2. The T1-05 page-switch disarm toast offers the same working link; the tool
   still drops to Move exactly as before.
3. The toast stays up ~6s and never blocks clicks outside its own card;
   Escape during the toast reaches the modal/tool ladder (T2-04 behavior
   preserved).
4. With no plan open, the link shows "Open a plan first." and opens nothing.
5. Toast wording and `#setScaleFirstText` textContent shape are unchanged;
   existing gate/room-sizer/scale-zone/ghost specs pass unmodified.
6. `npm run check` passes; the full Playwright suite passes locally.
