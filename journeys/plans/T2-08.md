## Problem (verified)

Four surfaces create a line type; only one hands you the pen. The picker's Create tab
arms the Line tool (`features/choose-create-line-type.js:105` sets `state.tool =
App.TOOL.LINE`), but the sidebar "+ Add" (`#lineTypeCreate`, app.js:3473) and the Quick
tab's "Add Line Type" (`#quickLineAdd`, features/quick-line.js:110) create + select the
type and leave `state.tool` NONE — the walker's naive path (sidebar + Add, then click the
plan) dead-ends with 3–4 wasted clicks on the app's heaviest daily activity. Counter
create arms its tool (features/counter.js:173), so the app itself teaches the expectation
the line side breaks. Separately: the New Polyline modal's "Create new line type" link
(`#polylineNewLineType`, app/index.html:737) has **no handler anywhere** — a dead link.
And `#quickLine` (app.js:3234) always routes through the Choose modal even when exactly
one line type exists — a pure re-choose tax.

## Design

One shared helper, four call sites, one deletion. **`app.js`** — add next to
`setActiveLineType` (app.js:2596), publish `App.armLineToolAfterCreate` in the registry
tail (beside `App.setActiveLineType`, app.js:6719):

```js
// T2-08: every line-type create surface hands the user the pen, exactly as
// counter create (features/counter.js) and the picker's Create tab already do.
function armLineToolAfterCreate() {
  if (!state.pages.length) return;          // palette prep, no plan open — nothing to draw on
  if (state.drawingPolyline) return;        // never abandon an in-flight polyline trace
  if (!getPageScale(state.currentPage)) { showSetScaleFirstToast('Quick Line'); return; }
  state.tool = TOOL.LINE;
  state.quickLineStart = null;
  collapsePagesSectionForPlacing();
}
```

Call sites (each replaces its inline pages-collapse triple; `updateUI()` stays the
caller's last line, after `hideModal`):
1. `#lineTypeCreate` (app.js:3473) — sidebar + Add, also reached by the tool
   right-click "Add line type…" (features/tool-context-menu.js:35-38).
2. `#quickLineAdd` (features/quick-line.js:110) — via `App.armLineToolAfterCreate()`.
   Makes the quick-creators guide claim ("active, and ready to trace") true.
3. `#createLineTypeCreate` (features/choose-create-line-type.js:92-111) — swap its
   `state.tool = …; state.quickLineStart = null;` + collapse triple for the helper.
   Behavior identical on the normal route (`#quickLine` gates scale before the modal).
4. `#quickLine` (app.js:3234) — single-type skip, after the existing scale gate and
   `quickLineStart` clear: `if (state.lineTypes.length === 1) {
   state.activeLineTypeId = state.lineTypes[0].id; armLineToolAfterCreate();
   updateUI(); return; }` — then `App.showChooseLineTypeModal()` as today.

**Dead link: remove, not wire** — delete app/index.html:737. Wiring would mean
modal-to-modal choreography that lands the user in Quick Line, not the polyline they
asked for; the link does nothing today, so removal is strictly no worse, and T2 #28
owns the zero-type "—" case with its Start-Drawing block.

**What does NOT change:** the picker's Choose-list row click (choose-create-line-type.js:58-67
— picking isn't creating) and `setActiveLineType`'s toggle semantics; the polyline flow
(`#polylineBtn`/`#polylineStart` — T2 #28's scope); counter create; the Set-Scale toast
wording (T2 #23 makes it a link); no new modals, ids, or CSS.

**Simplicity budget:** deletes a dead link, deletes three inline copies of the
pages-collapse triple, deletes one modal round-trip per Quick Line click for single-type
users, and deletes the "is it broken?" dead-click beat — the naive path becomes the
working path. Adds one 8-line helper; net surface shrinks.

## Risks & edge cases

- **Shipped T1-05 interplay**: the helper reuses the same `getPageScale` arm gate as
  `#quickLine`, so no new px-line hole opens; T1-05's page-switch recheck (renderPdf)
  protects the new arm paths unchanged.
- **Mid-polyline create**: the `state.drawingPolyline` guard keeps sidebar + Add from
  silently switching tools and orphaning clicked vertices (the T2 #22 work-loss class).
- **No plan open**: helper no-ops silently (create-before-upload palette prep, J16, stays
  frictionless). create-color-picker.spec.js drives `#lineTypeCreate` — confirm it stays
  green (the `pages.length` guard is what keeps it).
- **Chooser reachability at one type**: `#quickLine`/L skip the modal, but `#plumLineBtn`
  still opens it (Quick tab, tabbed), and sidebar + Add / right-click "Add line type…"
  cover creation — no route is lost.
- **T2 #28** (polyline dialog tax, later in the re-rank order) edits the same modal
  region of app/index.html and the `#polylineStart` handler — trivial rebase, no logic
  overlap. **T2 #23** edits `showSetScaleFirstToast` internals — this plan only adds
  call sites; #23's link upgrade then benefits them for free.

## Acceptance criteria

1. Scaled page: sidebar + Add → Create Line Type → footer flips to "Tap start point" and
   two plan clicks commit a run of the new type. Same via the Quick tab's Add and the
   picker's Create tab (the latter unchanged from today).
2. Unscaled page: every create surface still creates + selects the type, shows the
   existing "Set Scale ⚖ first…" toast, stays in Move, and plan clicks place nothing.
3. With exactly one line type on a scaled page, Quick Line (button, sidebar twin, or L)
   arms immediately with that type — no chooser; with two types the chooser opens as today.
4. `grep -rn polylineNewLineType` returns nothing; the New Polyline modal renders without
   the dead link and otherwise unchanged.
5. Creating a type from + Add mid-polyline-draw leaves the in-flight vertices and the
   Polyline tool untouched.
6. `npm run check` passes and the named specs pass locally with no console errors.
