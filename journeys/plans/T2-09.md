## Problem (verified)

While tracing a run there is no length anywhere until commit: the footer coaching slot
(`#statusMode`, `features/status-bar.js:165-167` — `'Tap end point'` for Quick Line,
`'Click to add points'` for Polyline) never shows a number, totals appear post-commit,
and per-line labels are opt-in via right-click → Show Length. Tracing to a target footage
or sanity-checking against a printed dimension needs a draw→check→undo→redraw loop or a
second pass with Measure. Everything needed is already live at mousemove time:
`handleCanvasMouseMove` ends in `updateStatus()` (app.js, grep `App.onDropPeekHover` —
the call sits just above it), `state.quickLineStart` / `state.drawingPolyline.points` /
`state.mousePos` are all PDF-space (the rubber-band previews at app.js:1825-1838 and
:1922-1937 consume them directly), and the Measure toast already owns the display format:
`formatDistFeetInches(distPdfPts, effScale)` (app.js:4910, geometry.js:268 — falls back
to `'N px'` with no scale).

## Design

One change, one file, plus two publish-only registry lines. In
`features/status-bar.js` `updateStatus`, the LINE and POLYLINE `toolHint` branches append
a live feet-inches readout while a draw is in progress:

- **Quick Line** (`state.quickLineStart && state.mousePos`): endpoint = `state.mousePos`,
  snapped via `App.snapLineToAngle(a.x, a.y, b.x, b.y)` when
  `state.lineTypeSettings.snapToHorizontalVertical` — byte-for-byte the preview's logic
  (app.js:1825-1829), so the number always matches the dashed line on screen. Build
  `tmp = { x1, y1, x2, y2, lineTypeId: state.activeLineTypeId }`;
  `pts = App.getLineLengthPdfPts(tmp, state.currentPage, false)` (arc-aware — an arc
  line type reads its true bezier length, correct since T1-06);
  `eff = App.getEffectiveScaleForLine(ann, tmp, false, state.currentPage)` with
  `ann = App.getActiveAnnotations(state.pages[state.currentPage])` — the exact pattern
  the Measure toast uses (app.js:4903-4910), so scale zones are honored.
  `toolHint = 'Tap end point — ' + App.formatDistFeetInches(pts, eff)`.
- **Polyline** (`state.drawingPolyline` with ≥1 point and `state.mousePos`): cursor
  snapped from the last vertex (mirror app.js:1928-1934); `tmp = { points: [...points,
  cursor], closed: false, lineTypeId: state.drawingPolyline.lineTypeId }`; same calls
  with `isPoly = true` → cumulative running total:
  `'Click to add points — 132\'-4"'`.
- **Wrap-cache key (mandatory)**: the one-line-only cache (status-bar.js:174-186, field
  feedback 2026-08-14) keys the forced layout read on `(composed text, bar width)` — a
  per-mousemove length would re-key every move and bring the thrash back. Key and
  measure on the hint with the readout replaced by a fixed worst-case placeholder
  (e.g. `— 88888'-88"`): the fit verdict is computed once per (static text, width) and
  is worst-case-stable, so a growing number can never wrap the bar mid-draw. The live
  string is swapped in after the cached verdict.

**app.js registry** (`// SECTION: App feature registry`, beside `App.formatFeet` at
~:6852): add publish-only `App.formatDistFeetInches = formatDistFeetInches;` and
`App.getLineLengthPdfPts = getLineLengthPdfPts;` (the latter is already a `window.*`
report.js global — this aliases it onto App per house rules; the window contract is
untouched).

**What does NOT change:** the Measure tool and its toast; the CHAIN rubber band (counter
chaining — no length semantics); committed-line surfaces, footer totals, per-line Show
Length labels; no new DOM, ids, or CSS; no state fields; touch paths (journey Mobile
field is "no" — the hint updates whenever `state.mousePos` does, nothing special-cased);
report.js `window.*` globals.

**Simplicity budget:** zero new chrome — text appended to the coaching slot that already
teaches this exact gesture; removes the draw-commit-check-undo loop and most per-line
label toggling; ~25 lines in one feature file + 2 registry lines. Spirit test: (1) no
added steps, (2) reads like pulling a tape, (3) makes the Measure double-check
unnecessary for most runs, (4) appears without being asked.

## Tests

House naming: `*.spec.js` = Playwright. Extend `footer-hint.spec.js` (owns the
`#statusMode` tool hint; keep its existing wrap tests untouched):

- "quick line shows live feet-inches readout": seed `state.pages[0].scale =
  { pixelsPerUnit: 9, unit: 'ft' }`, arm LINE, set `state.quickLineStart = {x:0,y:0}`,
  `state.mousePos = {x:90,y:0}`, `App.updateStatus()` → `#statusMode` contains
  `Tap end point — 10'-0"`; move mousePos → readout updates.
- "polyline readout is cumulative": `drawingPolyline.points = [{0,0},{90,0}]`,
  `mousePos = {x:90,y:90}` → contains `20'-0"`.
- "no scale reads px, never feet": scale null → readout matches `/— \d+ px/` and
  contains no `'`-quote feet string.
- "narrow bar still drops the whole hint": with a readout present, the borderline-width
  regime from the existing test drops hint+readout together (the worst-case key keeps
  the verdict stable).

No Node unit tests: no new pure helpers (all reused from geometry/line-metrics).

## Risks & edge cases

- **Wrap-cache thrash** is the real risk: keying the layout read on the live string
  would re-measure per mousemove — the placeholder key above is load-bearing, not
  polish. Verify with the narrow-bar test.
- **T2 #15 (toast rework, plan T2-04)** lands at slot 4 — five slots before this one —
  and moves the Measure "Distance:" readout to a `#statusMeasure` footer chip. This item
  deliberately stays inside `#statusMode` text, so the two compose; since T2-04 lands
  first, THIS plan is the second-lander and owns the reconciliation: verify the landed
  chip and the live readout read well side by side in the footer, and adjust wording
  here (not there) if they clash.
- **T2 #22 / #28** touch polyline Esc/start flow, not `updateStatus` — no shared lines;
  trivial rebase either order.
- **Shipped T1-05** lives in the same `updateStatus` function (totals block) and T1-06
  fixed arc length — anchor edits by grepping `'Tap end point'`, never line numbers.
- **Unscaled pages** are mostly unreachable while drawing (arm gate + T1-05 page-switch
  disarm), but a scale-zone-only page can arm — the `px` fallback keeps the readout
  honest, matching Measure.
- **Drops** are excluded (tmp line has none) — correct: drops are added in Line
  Properties after commit, not while tracing.
- **Touch**: no mousemove stream, so the readout updates only as `state.mousePos` does —
  today's hint behavior, no regression (Mobile: no).

## Acceptance criteria

1. Scale set, Quick Line armed, start point placed: moving the cursor shows
   `Tap end point — 12'-6"` live in the footer; the value at the end position matches
   the committed line's own length (45° snap and arc line types included).
2. Mid-polyline, the footer shows the cumulative length of clicked vertices plus the
   cursor segment, updating per move.
3. On a page with no usable scale the readout reads `N px` — never a feet number.
4. With no draw in progress every hint string is byte-identical to today; the existing
   footer-hint wrap test passes unmodified, and a growing readout never wraps the bar.
5. `npm run check` passes; extended `footer-hint.spec.js` and `quick-line.spec.js` pass
   locally.
