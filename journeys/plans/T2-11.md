## Problem (verified)

The same fixture shows two different totals inside one sidebar, and nothing on
screen labels either. With 7 Water Closet marks placed and 3 of them inside a ×3
multiply zone:

- **Counters section badge** — `features/sidebar-lists.js:74` sums raw
  `markers.length` over merged canvases: reads **7**.
- **Choose-tab badge** — `features/counter.js:64`, the identical raw expression
  (T1-11 deliberately matched it to the sidebar badge): reads **7**.
- **Summary** — `features/summary-list.js:57` (grouped) / `:131` (flat) sums
  `App.getMultiplyZoneForPoint(ann, m)`: reads **[13]**.
- **Footer** — `features/status-bar.js:42`: multiplied, **13**.
- **Legend** — `canvas-draw.js:699` (`drawLegend`): multiplied (current page).
- **Report + drill-down** — `report.js:77`/`:203`, `features/summary-detail.js:50`:
  multiplied.

So five surfaces say "with repeats" and two say "placed", with no words anywhere
(J18 walk: "the audit's first cross-check fails and the user can't tell which
surface is lying"; the ×3 story lives only in the dashed on-plan zone label). The
multiply-zone math itself (`geometry.js:147 getMultiplyZoneForPoint`, anchor-inside
rule) is correct and verified — this is purely a which-arithmetic-per-surface split.

One caution from the dossiers has since resolved: J18's note that the badge changes
semantics under "show only counters on current page" (then sidebar-lists.js:39)
predates the `sidebarFilterScope` refactor. Today the scope (`'off'|'page'|'project'`,
app.js:3613 `getCounterListFilterScope`) only **hides unused rows**
(sidebar-lists.js:59-70); the badge expression at :74 is all-pages in every scope.
The fix therefore lands in one expression per surface — but the specs must pin that
the scope modes can never fork the badge number again.

## Design

One decision, applied at the two raw call sites: **every counter total the user can
read is the multiply-adjusted ("with repeats") number**, and wherever repeats are
actually in play the surface says so in trade words via a `title` tooltip —
`"7 placed · 13 with repeats"`. No new chrome; when no zone touches a counter the
badges are byte-identical to today.

### 1. `geometry.js` — one pure primitive

Next to `getMultiplyZoneForPoint` (:147), exported in the CommonJS footer (:455):

```js
// Counter tally for one annotations object. placed = marks physically on the
// sheet; withRepeats = multiply-zone-adjusted total (the number every
// user-facing rollup shows — Summary, footer, legend, report already use it).
function counterTally(ann, counterId) {
  const markers = ann?.counterMarkers?.[counterId] || [];
  let withRepeats = 0;
  markers.forEach(m => { withRepeats += getMultiplyZoneForPoint(ann, m); });
  return { placed: markers.length, withRepeats };
}
```

**`app.js`** — publish `App.counterTally = counterTally;` beside
`App.getMultiplyZoneForPoint` (registry tail, app.js:6849). No `window.*` export —
report.js does not consume it (AGENTS.md contract untouched). ESLint needs no config
edit: the app.js group auto-derives geometry.js exports as readonly globals, and
features read it via `App.*`.

### 2. `features/sidebar-lists.js` — the Counters badge

`renderCountersList` (:74): replace the raw reduce with

```js
let placed = 0, withRepeats = 0;
state.pages.forEach(p => {
  const t = App.counterTally(App.getMergedAnnotationsForPage(p), c.id);
  placed += t.placed; withRepeats += t.withRepeats;
});
```

Badge text becomes `withRepeats`. When `withRepeats !== placed`, set on the badge
span: `title="${placed} placed · ${withRepeats} with repeats"`. When equal, no
title (no tooltip noise on the zone-free common case). The merged-canvas layer
convention (:62-64 comment, T1-11) is untouched; `usedOnPage` (:64) stays a raw
presence check — a mark is "used" regardless of multiplier.

### 3. `features/counter.js` — the Choose-tab badge

`populateCounterChooseList` (:64): the identical replacement + identical title
rule. T1-11 established that this badge and the sidebar badge must agree; they now
agree on the multiplied number.

### 4. `features/summary-list.js` — words only, numbers already right

- Grouped path (:56-58): add `placed: 0` to the record and `placed++` per marker in
  the same loop that adds `getMultiplyZoneForPoint`.
- Flat path (:129-132): accumulate `placed`/`withRepeats` via `App.counterTally`
  per page (keeps `getActiveAnnotations` — see What does NOT change).
- Both renderers (:95, :138): badge text stays `[total]`; when `total !== placed`
  add the same `title="7 placed · 13 with repeats"` on the row.

### What does NOT change

- **Summary, footer, legend, report, drill-down arithmetic** — already multiplied;
  they are the reference the badges converge to (J18 "keep": the drill-down is the
  crown jewel).
- **The layer axis.** Counters/Choose badges + footer tally MERGED canvases
  (T1-11); Summary/drill-down tally the active layer (G10's documented
  convention). This plan unifies the multiply axis only — do not "fix" merged vs
  active in passing.
- **Line-type surfaces.** Runs are placed-count and footage is multiplied on
  *every* line surface consistently (sidebar-lists:138-153, summary-list, footer,
  legend all via `getLineLengthSplitForTotals`) — no cross-surface disagreement
  exists, so no change; J6's runs-vs-footage asymmetry note stands as designed.
- **`features/item-details.js:160`** — per-page "Page 1: 7 markers" rows in the
  edit modal already self-label with placed language ("markers"); honest, keep.
- **`getMultiplyZoneForPoint`**, the zone tools, `child-counts.js` (already
  multiplied via `zoneUnits`), all `window.*` report.js globals, all modal markup.

### Simplicity budget (spirit test)

Removes the trust-which-number decision and the entire "why 7 vs 13?" double-take
/ support explanation class (J6 walker paused on it; J18's naive pass burned its
first cross-check on it). Removes the two-arithmetic split itself — after this,
one arithmetic, stated in the code by one shared primitive replacing two
hand-rolled raw reduces. Adds zero new UI surface: the only additions are a number
change inside two existing badges and a hover title. Trade words ("placed",
"with repeats"), not software words ("raw", "effective"). Findability holds
without the tooltip: the numbers simply agree everywhere, and the on-plan dashed
"×3" zone label remains the visible story of *why* the total exceeds the marks.

## Risks & edge cases

- **Counter-modal cluster (T2 #17+#18+#19) lands before this per the Stage-2
  order and edits `features/counter.js` create paths.** This plan touches only
  `populateCounterChooseList` — different functions, same file; rebase is
  mechanical but do it consciously. #16 (Quick Count icon/color) also lives in
  the quick-modals create path, no overlap.
- **Layer-axis residue**: on a multi-layer page, the Counters badge (merged) can
  still differ from Summary (active layer) — pre-existing G10 convention, out of
  scope. Keep the Playwright fixtures single-layer when asserting cross-surface
  equality, and say so in a comment so a future reader doesn't "fix" the spec.
- **Merged-ann multiplication**: a zone on layer A now multiplies a layer-B mark
  in the badge via the merged annotations object — exactly what the footer
  (status-bar.js:42) already does; parity with the footer is the goal, not a bug.
- **Viewer sessions**: view-link recipients see the sidebar lists (J6 walk shot
  07 showed viewers getting raw 7 vs Summary [13]); after this they see 13
  everywhere. Check `view-only.spec.js` for badge assertions and update
  deliberately if any pin the raw number.
- **render-pixels.spec.js baselines**: untouched — the legend (canvas) arithmetic
  does not change; the badges are DOM, outside the pixel fixtures.
- **Undo/redo of a zone**: badges recompute through updateUI like Summary does
  today (J6 verified one-step zone undo flips 13→7) — no cache to invalidate;
  the footer's own cache already handles zone edits via `invalidateFooterTotals`.
- **Tooltips are hover-only** (weak on touch): accepted — the fix is the numbers
  agreeing; the tooltip is a secondary explanation, and B9 (mobile batch) is the
  home for any coarse-pointer affordance work.
- **T2-15/#26, #29, B10 (legend "this sheet" label), B13**: no file overlap. B10
  will later label the legend's *scope*; this item deliberately leaves legend
  arithmetic and labels alone.
