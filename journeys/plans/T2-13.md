## Problem (verified)

Custom icons are a flagship, guided feature (CUSTOM_ICONS.md; the custom-icons
guide) whose only settings route is Settings gear → **Advanced** → Manage Icons
— behind a word that tells trade users "don't touch". Verified current state:
the opener button is `app/index.html:1852` (`#advancedManageIcons` inside
`settingsAdvancedModal`), wired at `app.js:4303`
(`hideModal('settingsAdvancedModal'); hideModal('settingsModal');
App.openManageIconsModal();`) — the **single** inbound call site
(features/manage-icons.js header confirms). The dossier-era sign-in gate on the
gear is gone (Tier-1 shipped since: `openProjectSettings` at app.js:4094 has no
auth branch, and custom-icons.md:29 already says "No account needed") — the
remaining confirmed problem is pure findability-by-construction: renaming,
reordering, and deleting icons is an *icon-picker* task, and the picker
(counter Create tab, `#counterIconCustomPanel` with its "+ Upload" cell,
app/index.html:619-622) has no route to it.

## Design

One move: the opener re-homes to where icons live; nothing about the Manage
Icons modal itself changes.

- **`app/index.html`** — (a) delete the `#advancedManageIcons` button
  (line 1852). (b) In `#counterCreatePanel`'s icon form-group, immediately after
  `#counterIconCustomPanel` (line ~622, inside the same form-group so it shows
  on both the Icon and Custom Icons sub-tabs), add one link row reusing the
  existing `.settings-menu-link` class (styles.css:718 — no new CSS):
  `<div class="settings-menu-links-row"><button type="button"
  class="settings-menu-link" id="counterManageIcons" title="Rename, reorder, or
  delete icons">Manage icons…</button></div>`.
- **`features/counter.js`** — one load-time binding beside `#counterChooseCancel`
  (line 107), house deferred-binding rule (read `App.*` at call time):
  `document.getElementById('counterManageIcons').onclick = () => {
  App.hideModal('counterModal'); App.openManageIconsModal(); };`
  Hide-then-open mirrors the old Advanced opener exactly and is load-bearing:
  the Escape chain checks `counterModal` (app.js:6285) *before*
  `manageIconsModal` (app.js:6319), so the two must never be visible together.
- **`app.js`** — delete the `#advancedManageIcons` handler line (:4303); update
  the pointer comment at :4058-4060 ("Advanced → Manage Icons" → the counter
  Create tab link in features/counter.js).
- **`features/manage-icons.js`** — comment-only: the header's "single inbound
  call site - Advanced -> Manage Icons" (lines 8-9) now names the Create-tab
  link. No logic change.

**What does NOT change:** `manageIconsModal` markup and all of
features/manage-icons.js's behavior (rename/reorder/edit-mode delete, Save
semantics, no `markProjectDirty`); `iconNames`/`iconOrder` persistence
(localStorage + IndexedDB backup + signed-in Artboard); the rest of
settingsAdvancedModal (Load test PDF, Export/Import Canvas, Canvas Repair,
cache tools — B18's shipped styling untouched); the Quick tab and ✎ details
modal custom-icon panels; the Escape chain; `App.openManageIconsModal`'s
registry contract (manage-icons.spec.js and scripts/build-screenshots.js:424
both call it programmatically — both keep working).

**Simplicity budget (spirit test):** removes one Advanced menu row (Advanced
shrinks toward repair/cache-only) and removes the three-hop
gear→Advanced→Manage-Icons detour for an icon task; net UI delta is −1 button
+1 link, zero new modals, zero new state, zero new settings, zero new CSS.
Fewer steps (icon management is now one click from the icon grid you're already
in); trade language ("Manage icons…" beside the icons, not "Advanced");
findable by a plumber who has never read a guide (it sits under the icon
picker). Bonus: mobile and signed-out users get a working route for free (the
counter modal is neither auth- nor desktop-gated), answering the dossier's
open-question line 137. Explicitly OUT of scope: auto-reopening the counter
modal after Manage Icons closes (zero new state wins; in-progress Create-tab
entries are discarded exactly as Cancel would).
