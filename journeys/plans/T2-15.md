## Problem (verified)

Trimming a combined set in the Prepare PDF modal is strictly one-sheet-at-a-time.
`features/prepare-pdf.js` exposes exactly Prev/Next/Delete/Undo/Rotate
(`#preparePdfPrev/Next` handlers :207-222, `#preparePdfDelete` :197-206,
`#preparePdfUndo` :186-196, `preparePdfRotatePage90` :223-232) over a single
`#preparePdfCanvas` preview (`app/index.html:2459`); no grid, range, or
keep-only control exists in the markup or handlers. Cutting a 200-sheet
combined set to a 15-sheet P-set costs ~185 Delete clicks, each one waiting on
a fresh pdf.js raster of the next preview (`renderPreparePdfPreview`, :26-76 —
`page.pdfPage.render` at :73, main thread). The dossier walked the 24→4-sheet
case at 20 clicks and confirmed the arithmetic; the persona this journey exists
for (combined-set estimator) gets the most clicks, and fatigue leads to "just
keep everything", which defeats the feature and bloats the 50 MB cloud budget.
Two adjacent confirmed papercuts are consequences of the same walk: Undo
restores a sheet without showing it (friction #6 — the handler deliberately
keeps the current sheet in view, :186-196), and the preview walk is the only
way to even *see* what's in the set.

Current modal reach (unchanged by this plan): signed-in fresh uploads via the
`promptLoadAnnotations` handoff (`features/pdf-intake.js:265`), append mode via
Project Settings (`pdf-intake.js:104`), the localhost test-PDF path (:45).
Signed-out fresh uploads still bypass the modal (gate at `pdf-intake.js:427`
requires `supabaseSession?.user`) — that is batch **B15**'s item, not this one.

## Design

One move: **the sheet set becomes a thumbnail grid with tap-to-keep/drop, and
the grid REPLACES the Prev/Next walk as the modal's default view.** The
single-sheet preview survives as the zoom view (entered per tile), keeping
Rotate, page rename, Delete/Undo, and the fixed-height letterbox exactly as
they are. "Keep none" + tap-the-keepers inverts the 185-click case into
1 click + 15 taps.

### 3. Logic — `features/prepare-pdf.js` (all new code stays in this file)

New module-locals beside the existing `preparePdf*` lets (:12-25):
`preparePdfView` (`'grid' | 'sheet'`), `preparePdfThumbCache` (a `Map`, key
`origIdx + ':' + rotation`, value jpeg dataURL), `preparePdfThumbGen`
(generation token), `preparePdfThumbQueue` (pending origIdx list),
`inFlightThumbTask`, `preparePdfGridObserver` (IntersectionObserver).

**`renderPreparePdfGrid()`** — builds one `.prepare-pdf-tile` per ORIGINAL page
index (0..`preparePdfPages.length-1`, original order — dropped sheets stay
visible so tap-to-restore replaces Undo in the grid). Each tile renders
instantly as a placeholder (sheet number + `page.label`, gray box) so a
200-sheet set is scannable and tappable before any raster lands; the label line
reads like the sidebar (`p3 · A-102`, ellipsized, full label in `title`).
Kept/dropped state = membership in `preparePdfKeptIndices` (which stays the
single source of truth — the commit path is untouched). The zoom button is
shown on kept tiles only (a dropped sheet is one tap from restored — deliberate
simplification, no read-only sheet view variant).

**Tap handling** (tile click): toggle membership — dropped→kept inserts sorted,
kept→dropped splices out (allowing 0 kept: `updatePreparePdfControls` already
disables `#preparePdfDone`/`#preparePdfDownload`/`#preparePdfSaveAndOpen` at
`kept.length === 0`, :93-97 — the empty set stays uncommittable). Update the
tile class, `#preparePdfGridStatus` ("Keeping K of N sheets"), and
`updatePreparePdfControls()`. Grid taps do NOT touch `preparePdfUndoStack`
(tap-again is the undo); the stack still serves sheet-view Delete unchanged.
`#preparePdfKeepAll` → kept = all; `#preparePdfKeepNone` → kept = `[]`; both
re-render tile states + status only (no thumb re-raster — cache keys are
untouched).

**Thumbnail pipeline** — the summary-detail pattern
(`features/summary-detail.js:20-33`: generation token bumped on open/close +
in-flight task cancel) married to the render-service seam:

- Lazy: an IntersectionObserver rooted on `#preparePdfGrid` enqueues a tile's
  origIdx when it becomes visible (and unobserves it). A single-flight async
  drain loop takes from the queue, checks `gen !== preparePdfThumbGen → stop`,
  checks the cache (`origIdx:rotation` hit → set `img.src`, done), else rasters
  at `THUMB_W = 140` px width (scale = 140 / natural viewport width, at the
  sheet's current `rotation`) into a detached canvas, then
  `App.renderAnnotationsToContext` is NOT called (prepare pages have no
  annotations yet — skip it), `toDataURL('image/jpeg', 0.8)` into the cache,
  set the tile img. Catch-and-skip per page like summary-detail :128-131
  (`RenderingCancelledException` is expected on close, not an error).
- The raster goes through the render-service seam so dense sheets go off the
  main thread when the worker is eligible: **app.js** publishes one new
  registry entry in the App feature registry tail (beside
  `App.__renderServiceStats`, app.js:6652):
  `App.rasterPdf = (params) => renderService.raster(params);` — the feature
  calls `App.rasterPdf({ pdfPage, scale, rotation, canvasContext, kind: 'thumb' })`
  and awaits `.promise`, keeping the returned handle in `inFlightThumbTask` for
  cancel. `render-service.js` needs NO change: `kind` is stats-keyed only
  (:253-256), unknown kinds route to slot 0, and the contract auto-falls back
  to MAIN while the prepare document adopts (or when the memory gate blocks a
  big doc) — exactly the designed behavior. The prepare document is its own
  pdf.js transport, so adoption is generation-guarded and the committed
  document re-adopts afterward on its own (see the render-service.js header
  contract).
- **Why not the pdf-tile-cache LRU**: `createPdfTileCache` keys on the
  *committed* document's pdfPage proxies × live zoom × effDpr and budgets
  full-page bitmaps; prepare thumbnails are fixed-140px rasters of a
  not-yet-committed document with a bounded lifetime. The per-modal `Map` (key
  includes rotation, so sheet-view Rotate invalidates exactly one entry) IS the
  whole cache; it borrows the tile-cache's self-validating-key discipline, not
  its instance. Cache + queue + observer are cleared in `closePreparePdfModal`
  (:146-153) and re-initialized in `openPreparePdfModal`; the gen token is
  bumped in both, and `inFlightThumbTask.cancel()` is attempted on close.

**View switching** — `openPreparePdfModal` (:99-145) sets
`preparePdfView = 'grid'` (both fresh AND append modes) and calls a new
`updatePreparePdfView()` that toggles `#preparePdfGridWrap` /
`#preparePdfSheetWrap` visibility; the name-tabs row and the actions rows stay
visible in both views. The tile zoom button → `openPreparePdfSheetView(origIdx)`:
`preparePdfCurrentIdx = preparePdfKeptIndices.indexOf(origIdx)`, view =
`'sheet'`, then the existing `renderPreparePdfPreview()` +
`updatePreparePdfControls()`. `#preparePdfBackToGrid` → `saveCurrentPageName()`,
view = `'grid'`, `renderPreparePdfGrid()` (re-reads labels renamed via the
"> Page Name" tab and rotation-changed cache keys — a rotated sheet's tile
re-rasters on next visibility). Gate the `computePageSizes` background loop's
`renderPreparePdfPreview()` refresh (:140-142) on `preparePdfView === 'sheet'`
(it repaints a hidden canvas otherwise); the loop itself is unchanged.

**Fresh-mode description** (:125) gets the §1 copy; append-mode copy (:121)
becomes "Tap the sheets you don't need, then add the rest to the project."

**Telemetry hook** — in BOTH commit buttons (`#preparePdfDone` :357,
`#preparePdfSaveAndOpen` :383), after `r.ok`:
`App.logUserEvent('prepare_trim', App.state.currentProjectId || null,
{ total: N, kept: K, dropped: N-K, mode: preparePdfMode })` where N is the
original page count captured at open. (`App.logUserEvent` is published,
app.js:6675; it no-ops signed-out — ambient rule, accepted.)

### Simplicity budget (spirit test, stated per JOURNEY-MAP rule 3)

Removes: the Prev/Next sheet-walk as the default route (~185 Delete clicks →
"Keep none" + ~15 taps for the persona case, each Delete no longer serialized
behind a full-preview raster); the Undo-hunt for a restored sheet in the
default flow (dropped sheets stay visible — friction #6 dissolves in grid
mode); the need to walk the set just to see what's in it; and the FEATURES.md
"reorder" lie (docs edit below — the dossier proved no reorder control exists).
Adds: one grid view + two bulk buttons inside the existing modal. Trade
language throughout: "sheets", "Keep", "Removed" — no "thumbnails"/"toggle" on
screen. Findable by construction: the grid IS the default view; fewer steps
and fewer decisions on the happy path.

- **Shipped Tier-1 behavior to preserve**: T1-08's append toast lives in the
  `#preparePdfDone` handler this plan edits (:366-370) — keep it, and keep the
  append-mode spec green. T1-01's backup/restore interacts only through
  `writeTakeoffStateBackup` after commit — untouched.
- **Sheet-view walk indexes kept sheets only** (existing invariant —
  `preparePdfCurrentIdx` indexes `preparePdfKeptIndices`). The zoom affordance
  is hidden on dropped tiles so the invariant never breaks; sheet-view Delete
  clamps `preparePdfCurrentIdx` as today (:203). Deleting down to few sheets in
  sheet view then returning to grid must re-render statuses — covered by the
  round-trip spec.
- **Zero kept**: representable now (Keep none). Commit/Download already
  disable at 0 (:93-97); `commitPreparePdfToState` also guards
  (`!kept.length → {ok:false}`, :244). Verify Delete in sheet view still
  disables at 1 kept (:89) — grid is the only route to 0.
- **Render cost / responsiveness**: 200 placeholder tiles are cheap DOM; only
  visible tiles raster (IntersectionObserver), one at a time, cancellable.
  Dense sheets off-thread when the render worker is eligible; automatic MAIN
  fallback (adoption in flight, memory gate, worker failure) is the seam's
  contract — no code branches on it. Worst case (~200 rendered thumbs at
  ~15-30 KB jpeg) ≈ 3-6 MB of dataURLs, freed on close. The `computePageSizes`
  PDFLib loop (per-page byte sizes) is pre-existing load; it now skips its
  hidden-canvas repaints in grid view.
- **Prepare-document adoption churn**: the render worker adopts the prepare
  doc's bytes, then re-adopts the committed doc (new transport) after Open —
  generation-guarded by design (render-service.js header). A >memory-gate doc
  simply stays MAIN. No render-service edits; if specs surface stale-raster
  weirdness, the fallback is `kind:'thumb'` rasters calling
  `page.pdfPage.render` directly (summary-detail does exactly this today) —
  a one-line swap that keeps the whole design.
- **`renderAnnotationsToContext` is deliberately skipped** (prepare pages
  carry no annotations) — if append mode ever previews existing pages, revisit;
  today it previews only the incoming pages (:104).
- **Mobile/tablet**: `minmax(120px,1fr)` tiles + ≥32px zoom button are
  touch-sized; tap = the primary gesture (the whole point). J2 is scoped
  Mobile:no, so no dedicated mobile spec — sanity-check the 92vw card at
  ~768px manually.
- **File size**: features/prepare-pdf.js grows to ~580 lines. The 2026-07
  decomposition audit's floor applies to app.js extraction candidates, not a
  cap on cohesive feature files — one modal, one file stands. Splitting a
  `prepare-pdf-grid.js` would add a precached file + index.html tag +
  PRECACHE_URLS churn for no boundary gain; rejected.
- **Spec churn**: the two updated walk tests must not weaken assertions — the
  sheet-view entry step is additive only.

## Acceptance criteria (walkable)

1. Opening Prepare PDF (registry open, signed-in fresh upload, or append mode)
   lands on the sheet grid: one tile per sheet, placeholders with sheet
   number + label immediately, thumbnails filling in as tiles scroll into
   view; scrolling stays responsive on a large set.
2. Tapping a tile drops it (dimmed + red ✕ "Removed", zoom hidden); tapping
   again restores it; `Keeping K of N sheets` tracks every change.
3. "Keep none" drops everything and disables Open / Save & Open / Download
   Trimmed PDF; tapping 2 tiles re-enables; Open commits exactly those 2
   sheets — labels and rotations carried (`state.pages` verified).
4. The 24-sheet dossier scenario is 1 click + 4 taps + Open (was 20 Delete
   clicks); the 200→15 case is 1 click + 15 taps (was ~185).
5. A tile's zoom opens today's single-sheet view for that sheet; Prev/Next/
   Delete/Undo/Rotate and both name tabs behave byte-for-byte as before
   (existing spec assertions untouched); "‹ All sheets" returns with renames,
   rotations, and deletes reflected in the grid (rotated sheet's thumb
   re-renders).
6. Append mode defaults to the grid and still toasts "Added N sheets to
   \<project\>" on commit (T1-08 spec green).
7. Cancel/Escape behaves exactly as today (silent discard — B15's confirm is
   explicitly out of scope); closing mid-thumbnail-load cancels cleanly with
   no console errors; reopening re-renders fresh.
8. Signed in, each commit logs one `prepare_trim` with
   `{ total, kept, dropped, mode }`; the event renders "Trimmed a plan set" in

9. `npm run check` passes (filemap + sw restamped); full local Playwright run
